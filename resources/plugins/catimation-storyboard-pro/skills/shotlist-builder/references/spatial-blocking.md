# 俯视空间图 / Top-Down Blocking

**规则:** 写任何含 2+ 角色、关键道具在特定台面、或机位几何要紧的提示词之前,先出
一张俯视图并拿到用户认可。AI 视频模型不会自己推理空间关系——不用绝对量把它写死,
它就编。俯视图是「写提示词之前先把调度锁住」的手段。

> 这套坐标系和画面占位不是一回事。**画面占位**说的是取景(谁在左三分之一、谁在
> 右三分之一);**场景占位**说的是几何(A 距 B 三米、C 在 A 后方 1.5 米被部分遮挡)。
> 两者互补,多角色场两样都要写。

## 1. 什么时候画

要画:

- 同一地点有 2+ 角色
- 关键道具放在特定台面上(设备、文物、武器、照片)
- 机位几何要紧(哪一镜从哪儿拍)
- 用户要求改位置——立刻重画

不用画:

- 泛用地点里的单人特写
- 与人物关系无关的插入 / 空镜
- 纯环境镜头

## 2. 图上要有什么

- **房间 / 地点轮廓**,标出墙、桌、屏幕、天桥等
- **每个角色**一个带首字母的彩色圆点(G、R、J、Re…),颜色跨场保持一致
- **每人一根视线箭头**(他在看哪儿)
- **道具**用可区分的图标或方块,标名字
- **距离**,以米为单位标在关键物件之间(`~3m`)
- **台面分区标签**(FL / FR / BL / BR — 前左 / 前右 / 后左 / 后右,相对声明的主视方向)
- **主轴**(如「南北 = 入口到屏幕」)供定向
- **每一镜的机位**,单独图标并编号

## 3. 怎么画(本 app / Codex 环境)

默认做法:**agent 自己写 SVG 文本**,存到
`<workspace>/assets/blocking/<scene>_topdown.svg`,然后用 `view_image` 给用户看。

这样做的理由:不依赖任何托管环境的绘图控件,可进版本控制,改一个坐标不用重画整张。
viewBox 用 `0 0 900 720`,深色底(`#18181b`)配高对比图形,圆点直径 40,字号 ≥14。

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 900 720">
  <rect width="900" height="720" fill="#18181b"/>
  <!-- 主视轴:从天桥入口(下)看向巨型屏幕(上) -->
  <text x="450" y="28" fill="#a1a1aa" font-size="14" text-anchor="middle">
    MAIN VIEW ↑ 从天桥入口看向巨型屏幕
  </text>
  <rect x="120" y="60" width="660" height="40" fill="#27272a" stroke="#3f3f46"/>
  <text x="450" y="86" fill="#e4e4e7" font-size="14" text-anchor="middle">巨型屏幕</text>

  <!-- 角色 -->
  <circle cx="450" cy="200" r="20" fill="#eab308"/>
  <text x="450" y="206" font-size="16" text-anchor="middle" fill="#000">G</text>
  <line x1="450" y1="220" x2="450" y2="330" stroke="#eab308" stroke-dasharray="6 4"/>

  <circle cx="410" cy="380" r="20" fill="#ef4444"/>
  <text x="410" y="386" font-size="16" text-anchor="middle" fill="#fff">R</text>
  <circle cx="490" cy="380" r="20" fill="#3b82f6"/>
  <text x="490" y="386" font-size="16" text-anchor="middle" fill="#fff">J</text>

  <!-- 距离标注 -->
  <text x="470" y="300" fill="#a1a1aa" font-size="14">~3m</text>

  <!-- 机位 -->
  <polygon points="450,640 430,680 470,680" fill="#22c55e"/>
  <text x="450" y="705" fill="#22c55e" font-size="13" text-anchor="middle">CAM 镜头2</text>
</svg>
```

用户正在 tldraw 画布上工作时,也可以直接在画布上摆圆点和箭头——同样要等他确认。

画完问一句:**「位置对吗?要改哪儿?」** 改到用户点头,再写提示词。

## 4. 认可之后:翻译成提示词段落

该场的每条提示词都要带一个 `⚠️空间布局` 块,内容镜像已认可的俯视图:

```
⚠️空间布局(MAIN VIEW=从 [方向],俯视图布局):
位置A:[角色1] 靠 / 站在 [确切位置]——[细节,如身高、朝向]
位置B:[角色2] 站在 [确切位置]——[细节]
位置C:[道具] 放置在 [确切位置]——[细节]
⚠️[关键对齐规则:距离、轴线、镜像、遮挡]
```

实例:

```
⚠️空间布局(MAIN VIEW=从天桥入口看向巨型屏幕):
位置A:<主体4>@图片4 站在中央通道最前方靠近屏幕,面朝三人。
位置B:<主体1>@图片1 和 <主体2>@图片2 在通道中间并肩站立,距 <主体4> 约 3 米,
面朝 <主体4> 方向。
位置C:<主体3>@图片3 站在 <主体1> 和 <主体2> 正后方 1.5 米处——不在他们旁边,
严格在他们背后,被他们的身体部分遮挡——也面朝 <主体4> 方向。
⚠️<主体1> 左肩与 <主体2> 右肩间距约 40 厘米。<主体3> 的头顶高度严格低于
<主体1> 和 <主体2> 的肩部连线(站位较远造成的视觉缩小)。
```

提示词里一定要写清:

- 米为单位的距离
- 相对声明主视方向的方位(东 / 西 / 南 / 北)
- 谁遮挡谁
- 每人朝哪个方向
- 模型容易搞错的身高或视线高度

## 5. 位置变更

用户在认可之后要改位置——**先重画俯视图**,重新拿认可,再改提示词。不要凭记忆直接
改提示词里的 `空间布局` 段;永远从最新那张认可过的图翻译。
