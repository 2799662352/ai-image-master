## 1. P0 闪退修复 — 模型直出 base64 图的全链路「物化」

### 问题

nano2 等 gemini-native 模型的 4K 图以 base64 内联在 JSON 里返回，一张 ≈ 10–40MB
字符串。修复前该字符串会：

1. 存进 zustand store（`resultUrl`）直到 COS 上传完成；
2. 原样经 IPC 结构化克隆传给主进程转存 COS（两个进程各持一份）；
3. COS 失败时被写进 history，之后每次全量保存都随整个数组反复 IPC + `JSON.stringify`。

三处叠加 × 并发 6 → 渲染/主进程 V8 堆 OOM → 应用闪退；且崩溃常发生在 history
写盘途中 → 文件截断 → 重启后历史记录全丢。

### 修复（对齐 Chromium/Electron 社区共识，参见 cherry-studio #13578）

base64 一到手就转成 Blob（堆外二进制）+ `blob:` URL（几十字节），V8 堆不再长期
持有任何 base64：

| 环节 | 文件 | 做法 |
|------|------|------|
| 物化 | `src/renderer/src/utils/imageResources.ts`（新增） | `materializeImageUrl(s)`：`data:` → `fetch().blob()` + `createObjectURL`；http 等原样透传；jsdom/失败回退原字符串 |
| 显示 | `useGenerateStore` / `useBatchStore` / `ResultGrid` / `BatchResultGrid` | store 只存 `blob:`/http URL；cosUrl 热切与删除项时 `revokeLater`（延迟 10s 防闪图） |
| 上传 | `cosUploadDispatcher.ts` + `src/main/index.ts` | 新增字节版 IPC `cos:enqueue-upload-bytes`（ArrayBuffer 结构化克隆，比 base64 小 25% 且不占 V8 字符串堆，上限 64MB）；旧 preload 自动降级回 from-url 通道 |
| 落盘兜底 | `src/main/index.ts` | 上传前先把字节写一份到 `userData/generated-images`，结果广播携带 `localPath`——COS 失败/断网时渲染端切 `local-file://` 显示并写进 history，「生成过的图永远找得回」 |
| history 参考图 | `HistoryDataService.ts` + `imageResources.ts` | `thumbnailRefsForHistory`：`data:` 参考图压成 640px JPEG dataURL（重编辑回灌够用，单张 ≈ 30–120KB）；同批 refs 按数组引用缓存，整批只压一次 |
| 旧数据清洗 | `StorageBridge.ts` | 保存时把 >1MB 的 `data:` 参考图条目就地替换为 `[base64-removed]`，老记录首次保存即完成一次性清洗 |
| history 写盘 | `src/main/index.ts` | `sanitizeHistoryValue`（>1MB `data:` 字符串拦截）+ `historyWriteChain` 串行化写，防非原子写导致的文件截断 |
| 历史页内存 | `DonorCard.tsx` | COS 源经 `appendCosThumb` 数据万象实时缩成 512px WebP；老 `data:` 条目经 `useDisplaySrc` 转 blob 后台解码，不卡主线程 |

## 2. Reference roots 白名单补齐 + 陈旧引用降级

设计文档: `2026-07-09-reference-roots-gate-design.md`（方案 B）

- **白名单不对称修复**：`AgentManager.assembleTurnInput` 调 `mapReferencesToInputItems`
  时补入 `<userData>/agent/uploads`，与 `fsIpc.resolveAllowedRoots()` 口径对齐。
  修复「从 ATTACHMENTS 树拖文件/编辑重发引用上传附件 → 预览正常但 Send 必被拒」。
- **陈旧引用降级**：`codexUserInput.ts` 的 `ReferenceInputMapping` 增加
  `skippedReferences`——`fs.realpath` ENOENT（跨机器/被清理的路径）跳过该引用不再
  throw，消息照发；路径存在但在 roots 外仍硬拒（隐私边界不变）。
- **用户提示**：跳过时经现有 notice 通道发 `kind: 'attachmentSkipped'` warning。

## 3. Codex 官方对齐 — userMessage 对账 + collaborationMode Plan 模式

设计文档: `2026-07-09-usermessage-reconcile-collabmode-design.md`

- **`clientUserMessageId` 写入侧**：我方 AgentMessage 行 id 随 `turn/start` 透传，
  rollout 的 `userMessage` item 回显为 `clientId`，codex 原生历史（thread/read、
  fork、resume）能映射回我方 DB 行。
- **`text_elements` 写入侧**：@mention 字节区间随 text input item 上报。
- **读取侧对账**：`codexNotificationRouter` 对 `userMessage` 的 `item/completed`
  不再直接 drop，产出内部事件 `user_message_reconciled`；`AgentManager` 按
  `clientId` 定位我方消息行，追加 `codexReconcile` 元数据块（codexItemId、
  localImages、textElements）。不透传渲染层、找不到行静默跳过（对账是增强，
  不是关键路径）。消费场景：「编辑重发」chip 的 stale-reference 兜底。
- **collaborationMode（Plan 模式）**：
  - 冒烟先行（`scripts/smoke-collaboration-mode.ts`，bundled binary 实跑）：
    `initialize` 带 `capabilities.experimentalApi: true` 被接受、
    `collaborationMode/list` 返回 presets、`turn/start.collaborationMode` 被接受。
  - 协议层：`CodexProtocolClient.listCollaborationModes()` RPC；
    `AgentInput.collaborationMode` spread-omit 透传（不传 = 行为不变）。
  - Plan preset 的 `reasoning_effort` 取自官方 mask 而非硬编码（官方语义：内置
    preset 不选模型，Plan 选 medium effort）；mask 拉取失败不缓存、下次 Plan
    turn 重试，降级 `reasoning_effort: null`。
  - 渲染层：composer 新增 `CollabModeToggle`（Plan/Default 按线程记忆，
    store `collabModeKind`）。
- **AttachmentService cleanup 引用感知**：清理过期上传文件前先扫描全部
  AgentMessage.items（`local-file://` URI + 原始路径双形态归一匹配），仍被聊天
  记录引用的文件不删——修复「悬空引用」把老线程附件 chip 弄断的 bug；扫描失败
  时 fail-safe 本轮不删任何文件。

## 4. `@` 统一 mention 弹窗 — 插件 / 技能 / 文件一体化

对齐 openai/codex MentionsV2（#19068，#27499 提升为默认）：

- **插件 mention**：`@token` 触发的弹窗现在把已装插件（`plugin/installed`，
  ≥0.140）排在文件之上；提交后 `@token` 留在文本里，`mention` input item
  （`plugin://<name>@<marketplace>`）随消息一起发（官方「文本 token 与 mention
  item 同行」语义）。`store.extractMentionTokens` 只在行首/空白后识别 `@`，
  邮箱和词中 `@` 不误触；发送侧按 path 去重，`@foo @foo` 不会激活插件两次。
- **技能进 `@` 弹窗**：插件组与文件组之间显示匹配技能，选中后插入官方
  `$name ` 标记，复用既有 `$`-token 发送管线；legacy `$` 触发保留。
- 键盘高亮走单一扁平列表（插件 → 技能 → 文件）；插件/技能组各限 4 条保证
  文件可达；mousedown 提交防 textarea blur 卸载弹窗。
