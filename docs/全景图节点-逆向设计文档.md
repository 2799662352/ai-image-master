# 全景图节点 · 逆向设计文档

> 逆向对象:无限画布(Vue Flow)里 image-node 上的「全景图」相机控制模式 + 工具栏「生成全景图」。
> 结论:该节点是 **两个独立模块拼接** 而成的「场景一致性」工作流 ——
> 1. **生成端**:用一套「360° 等距柱状全景图」提示词模板,把文字描述 / 参考图喂给图像模型,产出一张 equirectangular 全景图。
> 2. **消费端**:把这张全景图丢进一个 Three.js 全景预览器,内翻球贴图 + 自由环视,再「截图」导出普通透视图(单张 1920×1080 / 自动环拍 8 张)。
>
> 来源:
> - 飞书《场景一致性方案-全景图预览器》(提示词模板 + RunningHub 生图教程)
> - 本地 `全景图预览器.html`(Three.js 360 查看器,three r0.128)

---

## 1. 它到底在解决什么问题

普通图像模型一次只画**一个机位、一个视角**。当你想要「同一个房间的正面 / 侧面 / 背面」「同一场景的多个分镜」时,逐张生成会出现**场景不一致**:家具挪位、光影变向、材质漂移、空间结构对不上。

这个节点的核心思路:

> **先把场景「一次性、完整地」生成成一张 360° 全景图(包含前后左右上下的全部空间信息),之后所有机位的画面都从这同一张全景里「拍」出来。**

因为所有视角共享同一份等距柱状底图,天然就是**同一场景、同一光影、同一陈设** → 场景一致性问题被从「生成阶段」转移到了「采样阶段」,后者是确定性的几何投影,不会漂移。

## 3. 生成端:全景图提示词模板

「全景图」模式的本质,就是在用户输入外面**包一层固定的系统约束模板**,强制模型产出标准 equirectangular 全景,而不是广角图 / 鱼眼图 / 拼接分镜。

### 3.1 文生图模板

```text
请根据后续提供的详细描述，生成一张真正可用于360度观看的全景图。

技术要求：
- 画面必须为标准的 360° equirectangular（等距柱状）全景格式。
- 画面需支持完整的 360° 水平方向视野，并包含上方与下方的完整空间信息，形成可环视的沉浸式全景效果。
- 视点应基于单一固定观察点展开，保证整个场景是围绕观察者连续展开的，而不是普通广角图、鱼眼图、拼接感很强的图，或多个画面拼合的分镜图。

画面要求：
- 场景的前、后、左、右、上、下必须在空间逻辑上完整闭合，环绕关系自然，过渡连贯。
- 所有元素应符合统一的透视关系、比例关系、光影关系和空间结构，确保整体真实可信。
- 保持画面首尾衔接自然，避免左右边缘在拼接处出现断裂、错位、重复、结构冲突或明显接缝。
- 画面需具有沉浸感、空间延展感和真实环境包裹感。
- 细节应丰富、清晰，主体信息明确，整体构图适合在360全景查看器中观看。
- 不要生成普通单视角构图，不要生成平面海报式画面，不要生成多镜头拼贴效果。

输出目标：
- 最终结果应是一张高质量、完整、连续、可环视的 360° 全景图。
- 严格遵循后续详细描述中的内容、氛围、风格、材质、光线、色彩与关键元素要求。

以下是详细描述：
艺术风格：{风格，例如 写实风格}
描述：{具体内容，例如 现代客厅，温馨的灯光}
```

### 3.2 图生图模板(带参考图)

与文生图相同的技术 / 画面 / 输出约束,只是开头改为基于参考图、并强调**保持参考图元素不变**:

```text
请根据参考图，生成一张真正可用于360度观看的全景图，确保参考图中的元素保持不变。

（技术要求 / 画面要求 / 输出目标 同上）

{这里填写补充描述，如果不需要可以删除}
```

> 对应 DOM 里的「已连接参考图片 选中节点后在下方配置并生成」—— 节点支持接一张参考图走图生图模板。

### 3.3 生成约束要点

- **必须 equirectangular(等距柱状)**:这是预览器能正确贴到球面的前提。
- **单一固定观察点**:保证球心视点几何成立。
- **首尾(左右边缘)无缝**:贴到球上时 0°/360° 经线要接得上,否则环视会看到竖直接缝。
- 提示词里大量负向约束(不要广角 / 鱼眼 / 海报 / 拼贴)是为了把模型从默认的「单视角好看图」拉回到「可环视底图」。
- 模型不保证严格 **2:1** 宽高比,实战需要在生成后做比例校验 / 裁切(见 §6 注意事项)。

## 4. 消费端:Three.js 全景预览器(`全景图预览器.html` 逐段拆解)

一个零依赖(CDN importmap 引入 three r0.128 + OrbitControls)的纯前端查看器。核心是「**把全景图贴在一个内翻球的内壁,相机站在球心往外看**」。

### 4.1 场景搭建

```js
camera = new THREE.PerspectiveCamera(75, w/h, 0.1, 1000);
camera.position.set(0, 0, 0.1);        // 几乎就在球心

renderer = new THREE.WebGLRenderer({
  antialias: true, alpha: true,
  preserveDrawingBuffer: true,         // ★ 截图必须:否则 canvas.toBlob 拿不到像素
});
renderer.outputEncoding = THREE.sRGBEncoding;

const geometry = new THREE.SphereGeometry(500, 60, 40);
geometry.scale(-1, 1, 1);              // ★ 关键:X 翻转 → 法线朝内,贴图贴在球内壁
sphereMaterial = new THREE.MeshBasicMaterial({ color: 0x171310 }); // MeshBasic 不吃光照
const sphere = new THREE.Mesh(geometry, sphereMaterial);
```

三个要点:
1. **`scale(-1,1,1)` 内翻球**:把球的正面翻到内侧,这样站在球心能看到贴在内壁、且左右方向正确(不镜像)的全景。
2. **`MeshBasicMaterial`**:全景图自带光影,不需要场景灯光,用无光照材质 1:1 还原贴图颜色。
3. **相机在球心**:`fov=75`,通过旋转相机朝向来「环视」整张等距柱状图。

### 4.2 交互(OrbitControls)

```js
controls = new OrbitControls(camera, renderer.domElement);
controls.enableZoom = true;
controls.enablePan = false;            // 禁止平移,只能转 + 缩放视野
controls.minDistance = 0.1;
controls.maxDistance = 100;
controls.rotateSpeed = -0.5;           // ★ 负值:在球内,反向才符合"拖到哪看到哪"
```

- `enablePan=false`:全景只关心朝向,不允许把视点移出球心。
- `rotateSpeed = -0.5`:因为相机在球**内部**,正常方向会感觉反的,取负把手感纠正成「鼠标往左拖,视角往左转」。
- 渲染循环很常规:`requestAnimationFrame` → `controls.update()`(有阻尼/缩放需要)→ `renderer.render`。

### 4.3 载入贴图

```js
textureLoader.load(dataUrl, (texture) => {
  texture.encoding = THREE.sRGBEncoding;
  texture.minFilter = THREE.LinearFilter;
  texture.magFilter = THREE.LinearFilter;
  sphereMaterial.map?.dispose();        // 换图先释放旧纹理
  sphereMaterial.map = texture;
  sphereMaterial.color.setHex(0xffffff);// 从占位深色切回白色,让贴图原色显示
  sphereMaterial.needsUpdate = true;
  recenterCamera();
});
```

> 在**独立 HTML** 里图来自用户上传(`FileReader.readAsDataURL`);在**节点集成**里,这一步的输入直接换成「生成端产出的全景图 URL/DataURL」—— 上传 UI 被省略。

### 4.4 截图:把全景「拍」成普通透视图(这是整个方案的产出物)

#### 单张当前视角截图(1920×1080)

```js
// 临时把渲染目标切到固定出图尺寸
renderer.setPixelRatio(1);
renderer.setSize(1920, 1080, false);
camera.aspect = 1920 / 1080;
camera.updateProjectionMatrix();

renderer.render(scene, camera);
canvas.toBlob(blob => download(blob), 'image/jpeg', 0.95);

// finally: 恢复成屏幕尺寸 / pixelRatio / aspect
```

#### 自动环拍 8 张(每 45°,水平一圈)

```js
const baseYaw = getCurrentBaseYaw();        // 以当前朝向为起点
for (let i = 0; i < 8; i++) {
  const yaw = baseYaw - degToRad(i * 45);   // 每张 -45°
  camera.position.set(0, 0, 0);             // 截图时强制回到精确球心
  camera.lookAt(getTargetPosition(yaw, 0)); // pitch=0,水平环拍
  renderer.render(scene, camera);
  await download(`scene-${(i*45).padStart(3)}.jpg`);
}
```

涉及的两个数学函数:

```js
// 当前相机水平朝向(偏航角)
function getCurrentBaseYaw() {
  const dir = camera.getWorldDirection(new THREE.Vector3());
  return Math.atan2(dir.x, dir.z);
}

// 由 yaw(偏航)/ pitch(俯仰)算出朝向点
function getTargetPosition(yaw, pitch) {
  return new THREE.Vector3(
    Math.cos(pitch) * Math.sin(yaw),
    Math.sin(pitch),
    Math.cos(pitch) * Math.cos(yaw)
  );
}
```

截图期的关键细节:
- `isCapturing` 锁:截图期间 `onWindowResize` 直接 return,避免改尺寸把出图比例打乱。
- 截图前 `controls.enabled=false`、相机强制 `position.set(0,0,0)`,**剥离 OrbitControls 的缩放位移**,确保是纯方向投影。
- 全程用 `origPos/origQuat/origAspect/origPixelRatio` 备份并在 `finally` 还原,截完无感回到交互态。
- 出图固定 `1920×1080`、`pixelRatio=1`,与屏幕分辨率解耦,保证一致的导出尺寸。

## 5. 端到端运行逻辑(节点视角)

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 选中 image-node → 相机控制切到「全景图」模式               │
│    (camera-control-btn--active)                              │
│    => 生成参数套用 §3 全景提示词模板                          │
├─────────────────────────────────────────────────────────────┤
│ 2. 配置:填风格/描述,或连一张参考图(图生图)               │
│    点生成 → 调 RunningHub 图像 API(实测 GPT Image 2)        │
│    节点显示「图片生成中 / 取消」(flowing-border is-loading)  │
├─────────────────────────────────────────────────────────────┤
│ 3. 产出 360° equirectangular 全景图(挂回该节点)             │
├─────────────────────────────────────────────────────────────┤
│ 4. 工具栏「生成全景图」下拉 → 打开全景预览器                  │
│    把这张图作为纹理贴到内翻球(§4.3)                         │
├─────────────────────────────────────────────────────────────┤
│ 5. 自由环视(OrbitControls)→ 截图:                          │
│    · 当前视角 1张(1920×1080)                                │
│    · 自动环拍 8张(每45°)                                    │
│    => 得到「同一场景的一致性多视角图」                        │
├─────────────────────────────────────────────────────────────┤
│ 6. 截图回流画布:作为新图片节点 / 下游参考图,继续生产        │
└─────────────────────────────────────────────────────────────┘
```

**一句话**:全景图模式 = 「**生成一张可环视底图**」+「**从底图里采样任意机位的普通图**」。前者保证一致性,后者提供多视角产能。

## 6. 复刻 / 集成到本项目的注意事项

如果要把这套搬进 catimation(本仓库已是 React + three `^0.184.0`),注意:

1. **three 版本 API 差异(r0.128 → r0.184)**
   - `renderer.outputEncoding = THREE.sRGBEncoding` → 改 `renderer.outputColorSpace = THREE.SRGBColorSpace`。
   - `texture.encoding = THREE.sRGBEncoding` → 改 `texture.colorSpace = THREE.SRGBColorSpace`。
   - 其余(SphereGeometry / OrbitControls / scale(-1,1,1))一致。
   - 本项目已用 `three/addons/controls/OrbitControls.js`,可直接复用(参考 `ThreeGlobe.tsx` / `ThreeLightScene.tsx` 的全屏 OrbitControls 接法)。
2. **`preserveDrawingBuffer: true` 必开**,否则 `canvas.toBlob` 截不到像素;代价是禁用了部分浏览器的缓冲优化,常驻预览有轻微开销 —— 可只在预览器实例上开。
3. **等距柱状比例**:贴球要求底图近似 **2:1**。图像模型(GPT Image 2 等)不保证严格 2:1,建议生成后:
   - 校验宽高比,偏差大时居中裁切或外扩到 2:1;
   - 或在提示词里追加目标分辨率约束。
4. **接缝**:模板已强调首尾衔接,但模型仍可能在 0°/360° 经线留下竖直接缝/重复,环视时左右边缘可见。可考虑:边缘羽化、或选「接缝感最弱」的候选。
5. **截图相机要剥离交互位移**:务必像原版那样在截图前 `position.set(0,0,0)` + 关 controls,保证纯方向投影,避免缩放导致的视野不一致。
6. **内存**:换图 `map.dispose()`、卸载时 `renderer.dispose()` / `forceContextLoss()`(与本项目现有 Three 组件的处置规范一致)。
7. **从生成直连预览**:节点里跳过上传 UI,把生成结果 DataURL/URL 直接喂 `loadPanorama()`;若是远程 URL 注意 `crossOrigin='anonymous'` 否则 `toBlob` 会因画布被污染而抛错。

## 7. 参数速查表

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 球体 | `SphereGeometry(500, 60, 40)` + `scale(-1,1,1)` | 内翻球,半径 500,经纬细分 60×40 |
| 材质 | `MeshBasicMaterial` | 无光照,1:1 还原全景贴图 |
| 相机 | `PerspectiveCamera(fov 75)`,位于球心 | 环视底图 |
| 旋转手感 | `rotateSpeed = -0.5` | 球内反向修正 |
| 平移 | `enablePan = false` | 仅转 + 缩放 |
| 单张截图 | `1920 × 1080`,JPG `quality 0.95` | 固定导出尺寸 |
| 环拍 | `8` 张,步进 `45°`,`pitch = 0` | 水平一圈 |
| 纹理过滤 | `LinearFilter`(min/mag) | 平滑 |
| 色彩空间 | sRGB(r184 用 `SRGBColorSpace`) | 颜色正确 |
| 截图前提 | `preserveDrawingBuffer = true` | 否则截不到 |
| 生图 | RunningHub API,实测 GPT Image 2 | 模型可替换 |

## 8. 小结

- **节点 = 提示词模板(生成 360 底图)+ Three.js 全景预览器(从底图采样多视角)**。
- 一致性来自「**一次生成、多次几何采样**」,而非「多次生成靠运气对齐」。
- 预览器是标准的「内翻球 + 球心相机 + OrbitControls」全景方案,产出物是它的**截图能力**(单张 / 环拍 8 张)。
- 复刻关键三件套:`scale(-1,1,1)` 内翻球、`preserveDrawingBuffer` 截图、截图时剥离交互位移并固定 1920×1080。
