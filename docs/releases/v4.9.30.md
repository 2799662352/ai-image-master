# v4.9.30 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.29

## 概述

修两个问题:① 在 Codex 页的 DeepSeek(火山)和千问之间来回切换后发消息,报「This chat uses X, but your current provider is Y」;② 运镜知识库的 Sakuga 数据集检索,用「包含某标签」过滤时静默返回「无结果」。

**请注意:为了修 ①,本版内置的 Codex 内核从 0.166.0 换成了官方预发布版 0.168.0-alpha.3**(官方稳定版目前还是 0.166.0,修复只在预发布里)。

## 变化

- **修复切换提供商后发消息报错**。4.9.27 起内置的 Codex 0.166.0 加了「线程保存的提供商必须等于当前配置的提供商」的检查,切换后旧对话和我们切换时新建的分叉对话都会被拒。官方随后撤销了这个限制(openai/codex #59503),本版采用包含该修复的 0.168.0-alpha.3。同一套本地模拟端点的对照冒烟:0.166.0 上分叉后发消息报与截图相同的错误,0.168.0-alpha.3 上成功命中新提供商。
- **Sakuga 数据集标签过滤不再静默返回空**。数据集的 `like` 只支持前缀匹配,`user_tags like '%smears%'` 这种「包含」写法能通过解析、匹配不到任何文档,而且不报错。现在对 `user_tags` / `anime_tags` 的 `like` 条件改为在召回的候选(最多 100 条)里本地按整词匹配;零命中时会明确说明「只在这批候选里没有」,而不是「数据集里没有」。只处理用 `and` 连接的条件,含 `or` / 括号的原样交给上游。
- 升级 Codex 内核时的维护改动(不影响使用):预发布版本号现在能被正确识别,不会每次启动都重新下载;每日自动升级不会把预发布内核降回稳定版;内核下载加了超时和重试。

## 注意

- **本版 Codex 内核是预发布版**(比 0.166.0 多约 300 个提交,发布说明为空),我们只做了冒烟和自动化测试,没有逐项审查。如果遇到 Codex 页行为异常,请反馈;官方稳定版包含该修复后我们会换回稳定版。
- 在已打开的对话里直接换提供商,仍然是由我们在后台新建一个分叉对话来承接(这是 Codex 的限制,0.168.0-alpha.3 也一样),只是现在分叉后的对话能正常发消息。
- 已安装应用里如果手工改过 `resources/cinematography-kb-mcp/index.js`,更新会覆盖掉,以本版为准。

## 已验证

- 提供商切换的前后对照冒烟(见上);Codex 启动、resume、记忆、压缩四个冒烟全部通过;`src/main/agent` + `src/main/mcp` 158 个文件 1890 条测试通过。
- Sakuga 过滤新增 29 条测试(含模拟「前导 % 的 like 回空集」的端到端),20 种变异检查全部被抓到。
- `typecheck:ci` 无新增;所有 CI 检查通过。

## 还没覆盖的地方

- **没有在真实窗口里用真令牌在 DeepSeek 和千问之间各发一轮**(要用令牌且会扣费),上面的证据来自本地模拟端点 + 真实二进制。
- **没有对真实 DashVector / 网关跑过 Sakuga 新过滤**;本地过滤只在前 100 条候选里找,不是全库扫描;`anime_tags` 的真实分隔符没核实(按空白和逗号都拆)。
- 预发布内核的记忆库迁移目录没有核对;回退到 0.166.0 对本地库是否安全,只依据迁移文件数一致,没有实测。
