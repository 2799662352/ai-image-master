# v4.9.17 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.16

## 概述

视频工作台现在可以让多个 Agent 对话同时各填各的剧、各填各的一集,而且重试、并发都有保护;「视频工作台」技能从这一版起真正随应用安装;内置 Codex 升到 0.164.0。

## 新增:多个对话同时填视频工作台

以前所有 `video_workbench_*` 工具都读同一个「屏幕上的当前剧」,同时跑几部剧的时候,几个对话会来回把你的工作台切走,后一次写入还会落进别人的剧里。现在:

- **每个对话绑自己的剧**:`switch_project` / `create_project` 之后,这个对话的加卡、提交、改规格、导出、查看状态都只作用于它绑定的那部剧,不再读屏幕。没绑过的对话回落到屏幕上的那部剧(和以前一样)。
- **同一部剧里不同集数也各管各的**:`switch_project` 新增 `boardId`,对话可以钉在某一集(分段)上,你在界面里翻页也不会带偏它。被别的对话占着的剧 / 分段会在 `list_projects` 里标出来;没选剧、而落点恰好是别人占着的那一集时,写入会被拦下并提示先选剧,读不拦。
- **屏幕不乱跳**:只有当前没有别的对话在别的剧里干活时,屏幕才会跟过去;结果里会告诉你它在哪部剧里填、要不要去看。
- **重试不会出重复的卡**:`add_tasks` 新增 `clientRef`,同一分段内同一个键重放不会重复建卡、重复提交。
- **别人改过的卡不会被盲写覆盖**:`update_task.expectedRev` / `set_spec.expectedRevs`,版本过期则这一条不写,并回带这张卡现在的样子,让模型重新决定。不带则行为和以前完全一致。
- **整页提交不再重复花钱**:整页 `start` 默认跳过「已经出过片、且没改过」的卡,并在回执里说明;点名卡、界面上选中、或传 `includeSucceeded:true` 才会重跑。
- **每次调用带回「别人改了什么」**:`changedSinceYourLastCall` 列出自你上次调用以来别人加 / 删 / 改 / 重排了哪些卡;后台状态变化不会刷屏。
- 没有对话身份的调用(界面直接调用)行为不变。

## 修复:「视频工作台」技能随应用安装

这个技能 8 月起就被写成「随应用打包」,但应用的安装清单里一直没有它,所以全新安装的用户没有这个技能,只有自己从市场装过的人才有。现在:

- 启动时随应用安装,全新安装即可用。
- 以前从市场装过的用户:如果副本内容和应用自带的一致,或者是已知的历史版本,启动时会被应用接管并更新到当前版;**你自己改过的副本不会被动**。
- 同一个目录只会有一份,不会出现重复技能。
- 加了一道检查:以后改这个技能(或 `ffmpeg-win`)的内容却忘了登记,CI 会直接报错并给出要追加的内容。

## 其他

- 内置 Codex CLI 升到 **0.164.0**。
- 插件商城 `catimation-video` 升到 **1.0.45**(带多对话写入安全的使用说明)。已经装过这个插件的用户需要重新安装一次才会拿到新版(没有查到自动升级)。

## 还没覆盖的地方

- **没有用两个真实的 Agent 对话同时各填一集完整跑过一轮**,这次的验证是单元测试 + 工具执行器级测试 + 入参 schema 守卫。发布后会开两个对话实际验证。
- 撤销 / 重做栈仍然是整个工作台一个,另一个对话触发的撤销会作用到全局最近一步。
- 对话与剧的绑定、「别人改了什么」的基线只保存在内存里,重启应用后需要重新 `switch_project`(未绑定的写入有保护,不会串进别人的剧)。
- 素材转存等后台事件也会推高卡的版本号,偶尔会出现一次误报的冲突;回包里带着这张卡现在的样子,按它重试一次即可,连续两次冲突模型会问你。
- 「已知历史版本」的接管检查目前只覆盖 `ffmpeg-win` 和视频工作台。其余既随应用、又随插件交付的技能,装了插件之后更新权归插件,这是之前就有的行为。

其余 4.9.16 的功能不受影响,无需重新设置。
