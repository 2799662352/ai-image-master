## 概览

一条主线:**子代理(多智能体)从不可见变成可见、可归属、可计费、可停止**。

起因是一次核查:捆绑的 Codex 0.145 里,多智能体能力**默认就是开着的**——模型的
系统提示词里本来就写着它是一个代理团队的主控,并给了它孵化、等待、中断子代理的
工具。而我们的界面此前完全不认识这套东西。

## 子代理

- **工具调用不再落错会话(正确性修复)**:子代理调用生成图片、或向用户提问时,
  此前会归属失败并退回"当前打开的那个会话"——图会出现在你碰巧正在看的对话里,
  提问卡片会弹给一个毫不相干的会话。现在按孵化关系正确归属。
- **停止会真的停下**:此前按下停止只结束主对话这一轮,已经派出去的子代理会继续
  跑完——你取消掉的工作仍在花钱。现在连带停止属于该对话的子代理。
- **委派卡片**:父对话里能看到一张卡,显示交出去的任务、使用的模型、以及每个子
  代理的状态与它的回复。子代理可以跑与主对话不同的模型,所以模型名单独列出。
- **状态如实显示**:子代理有完成、失败、被中断等多种结局,此前只有"完成"被认出来,
  其余一律显示为"仍在工作"——一个已经失败的子代理会把错误信息摆在转圈图标旁边,
  用户会一直等下去。现在分为完成 / 失败 / 停止 / 进行中四种。
- **子代理花费**:每个子代理消耗的 token 显示在它自己那一行。刻意不并入主对话的
  用量统计——那个数字驱动上下文窗口指示器,混入子代理的数据会让你以为主对话的
  上下文快满了。
- **多智能体 V2**:在实测验证过的两条 GPT 通道上启用。代理显示为上游给这次孵化
  分配的名字(如 "Newton"),而不是 UUID,也不是代理定义文件的路径——名字只存在
  于子代理自己的线程记录里,与 Codex 终端自己的代理列表取自同一处。Claude 与 Grok
  通道保持上一代,因为 V2 会加密交给子代理的任务,而非 OpenAI 后端能否解开尚未验证。
- **迟到的子代理消息不再串台**:子代理会活过主对话的这一轮,它的花费与完成状态
  常常在你已经发出下一条消息之后才回来。此前这类更新只会往最后一条消息里找卡片,
  找不到就凭空新建——于是新对话里会多出一张空的委派卡。现在更新回到它原本那张卡上。
- **稳定性**:子代理的事件此前会无声地堆积在一个永不清空的缓冲区里,填满之后会
  开始丢弃主对话真正需要的数据(表现为回复偶尔丢开头几个字)。现在不再堆积。

## 已知未做

- 应用重启时若有子代理在运行,重启后无法与它们重新建立联系,那张卡会一直停在
  "进行中"。
- 在 V2 通道上,委派卡片显示不出交给子代理的任务原文与它使用的模型(上一代可以)。
  这一条经实测确认**拿不到而非没做**:子代理的线程记录里没有模型字段,它的历史里
  也没有承载任务原文的条目——V2 把任务加密注入,不落成可见记录。
- 界面上没有"让子代理做这件事"的入口,也没有任何东西提示模型何时该委派——所以
  除非你在对话里明确要求,子代理不会自己出现。
