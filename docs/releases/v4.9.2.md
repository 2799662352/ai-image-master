# v4.9.2 发布说明

> 更新渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 存档
> 上线版本：v4.9.1

## 概述

腾讯渠道上了 GPT Image 2.5：模型列表里的「腾讯」一簇从两条变成四条——腾讯 Image 2 / Image 2 Fast / **Image 2.5 Flare** / **Image 2.5 Sunburst**。后两条与 apiyi 官转的 2.5 是同一个模型、不同的线：走腾讯 TokenHub og-image 渠道，与 Image 2 Fast 同价（比官转便宜），并且**可以走平台余额**。

## 腾讯 Image 2.5 Flare / Sunburst

- **能力与官转 2.5 一样**：清晰度五档（低 / 中 / 高 / 超高 / 最高，默认「高」，档位说明标了与 2 代的对应关系，不再显示按官转价折算的美元数）、一次出 1–4 张、**透明背景**、**遮罩局部重绘**。Flare 速度优先（约 20s），Sunburst 画质与改图精度优先（约 40s）。
- **参考图 / 遮罩传的是 URL**：本地图片先直传云端拿地址再提交，不走 base64；改图一次固定 1 张。
- 聊天抽屉的出图渠道选择器多了「腾讯Flare」「腾讯Sunburst」两项；Codex 的 `generate_image` 可直接传 `custom-model-og-v2.5-f` / `custom-model-og-v2.5-s`，透明底与 `maskImage` 在这两条上都生效。
- 出图技能文档同步：用户说「腾讯 2.5 / 腾讯 flare / 腾讯 sunburst」或「要 2.5 但走平台额度」时，agent 会选这两条。

## 灯箱「擦除」跟随你选的渠道

擦除仍只绑 GPT Image 2.5。变化是：聊天里选了腾讯 2.5 的话，擦除会点名腾讯线（走平台余额，不会悄悄换回官转）；选的是没有遮罩能力的渠道（腾讯 Image 2 / 万相 / Nano 等）时，照旧回落到官转 Sunburst。

## 实测

生产网关走平台余额：透明底文生图返回带 alpha 通道的 PNG（约一半像素全透明）；遮罩去掉苹果果柄，遮罩内 55% 像素重绘、遮罩外 4.8%，与官转 Sunburst 对照组（58% / 2.1%）一致，腾讯线 25s、官转 141s。

其余 4.9.1 的功能不受影响，无需重新设置。
