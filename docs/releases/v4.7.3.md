# v4.7.3 发布说明

> 更新渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 存档
> 上线版本：v4.7.2

## 概述

这一版围绕**「钱从哪个钱包出、请求发给谁」**这条链路，修掉一组表现完全一致、成因却各不相同的故障，并接入了万相 3.0 Prime。

这些故障的共同特征是**无声**：请求返回 200 或 401，视频照出、钱照扣，而错误里没有任何一个字能指向成因。同一天里它们连着出现了三次，每次都要靠翻代码加对着网关反复实验才能定位——所以这一版除了修，还给这条链路补了诊断和守卫。

## 登录之后仍在扣自己的 Key

登录了、余额也显示出来了，出视频却报一句 `401 无效的令牌`。

根因是**凭据落盘了、但「用哪个计费池」没落盘**。于是每次重启，主进程手上是「有钥匙却不知道开哪把锁」，视频那条路判不出平台余额可用，静默退回用户自填的 Miau Key——而那个位里可能存着一个早就失效的值。

难查的地方在于它极具迷惑性：余额是对的、登录是对的、聊天也在正常扣平台余额，唯独视频在扣另一个钱包。

### 改法

计费池与凭据一起落盘，主进程启动即就绪；渲染层的计费意向随之跟随登录态起手。**登录就是平台余额，登出才回自填 Key，Key 填没填对都不影响登录态下的行为。**

## 记忆任务跑在过期的模型选择上

在聊天里切到便宜的模型之后，账单里仍然出现大量贵档模型的消费。

后台的跨会话记忆任务，其模型是在引擎启动那一刻**钉死**的。之后在选择器里换模型只改对话那一路，记忆那两条纹丝不动。实测一轮下来，对话花了 ¥0.10，而背后的记忆任务花了 ¥2.14——用户在界面上看到的选择与实际扣费完全对不上。

现在记忆任务固定跑在各通道最便宜的档位上：它本来就是总结活，用不着贵的那一档。

## 万相 3.0 Prime

视频工作台与「生成视频」工具新增 `万相 3.0 Prime`。能力与万相 3.0 完全相同（同样的模式、素材上限、时长与分辨率），差别只有上游模型与单价（约 1.33 倍），费用估算已按实测价差跟进。

> 已知限制：Prime 目前经网关提交时参考素材不生效，正在网关侧处理。需要参考图/参考视频的场景请先用万相 3.0。

## 其它

- **环境隔离**：安装包不再受开发用环境变量影响，始终连生产；换过环境的机器不会再复用上一次留下的陈旧凭据。
- **诊断**：视频提交会记录一行摘要（打给谁、用哪种钱、带了几件什么素材），凭据类错误也会带上这两项——同一句 `401` 不再需要靠翻代码区分成因。
- **图像理解与万相直连**补齐平台余额支持，此前这几条只能用自填 Key。
- **运镜知识库**明确只认设置里的 Key，登录与否都不改变它的行为。
