# v4.5.4 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.5.3

## 概述

修文件面板「点开视频卡死」。用户报告点 workspace 很卡、有时候整个应用僵住,
素材目录里有几百个文件、上百个是 mp4/png。

## 点开媒体不再卡死

真凶不是文件多,也不是缩略图 —— 文件树根本不生成缩略图,目录列举也一直是异步的。

是**点开一个图片或视频的那一下**:文件被整份读进内存、编码成 base64、经 IPC 送到
界面层,然后用一个**逐字节的循环**还原回来。一个 50MB 的视频,那个循环要跑 6700 万次,
全在界面线程上 —— 窗口在这期间完全停止绘制,Windows 会显示「未响应」。

现在把解码交给浏览器内核的原生实现,没有那个循环。聊天和视频工作台的媒体走的是同一段
代码,一并受益。

## 越用越卡也修了

打开工作区时会注册一个文件监视,**之后每打开一个文本文件又注册一个**,而它们从不注销。
打开 20 个文件之后,保存一次会让界面收到 21 条相同的变更通知,于是重新列 21 次目录、
把整棵文件树重画 21 遍。这解释了为什么是「**有时候**卡死」——取决于这一会儿开过多少文件。

顺带让文件监视跳过 `.git` 和 `node_modules`(对齐 VS Code 的出厂设置)。这两个目录
文件极多、变动极频繁,而且本来就不显示在树里 —— 之前它们不出现在界面上,却仍在被
逐个监视。

## 文件树点选更跟手

展开一个文件夹以前会让整棵树重画,现在只重画真正变了的部分;点选一行也只影响那一行,
而不是列表里的每一行。

## 顺带

- 发版流程里所有网络请求加了超时。上一版发布时有一步卡了 18 分钟直到超时被取消,
  原因是有重试但没有超时 —— 连接挂起时既不返回也不报错,重试根本不会触发。
- 修正了 4.5.3 里一处新引入的问题:文件面板的图片/视频预览曾短暂改用一种流式协议,
  在 Windows 上因为一个上游缺陷(路径的盘符会在解析时丢失)而无法加载,已改回。
