# v4.9.20 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.19

## 概述

三处界面问题的修复:**浏览器登录点「取消登录」会误报网络故障、之后退不出去**,**设置里「使用明细」展开其余模型后撑破面板、挤没下面的调用记录**,以及**「使用明细」的消费合计把「已扣除退款」写成了「不含退款」**。

## 修复:取消登录误报「无法连接登录服务」,错误态没有退出路径

- **现象**:浏览器登录时点「取消登录」,弹出「无法连接登录服务,请检查网络或代理」,而且之后没有任何按钮能退出这个提示,只能重启应用。
- **原因**:有两个叠加的问题。一是取消时本地回调监听器用一个普通错误结束等待,错误归类认不出它,落进了「网络故障」的兜底分支;而且重复点登录时,上一轮的取消会把新一轮的等待状态盖成错误。二是错误态里没有任何动作能把错误清掉,登录遮罩就一直停在错误页。
- **现在**:
  - 主动取消一律**静默**,不再弹任何错误;重复发起登录不再被上一轮的取消干扰。
  - 等待超时(5 分钟没完成浏览器授权)单独提示「等待浏览器授权超时,请重新发起登录」,不再说成网络问题。
  - 错误态新增「先用 API Key 继续」按钮,并说明不登录也可以自己填 Key 出图。
  - 支持 `Esc`:等待态下等于取消登录;错误态下关闭提示;登录成功的画面不响应 `Esc`。

## 修复:使用明细展开其余模型后撑破面板

- **现象**:设置 → 使用明细,点「展开其余 N 个模型」后,模型列表按内容高度全部摊开(几十个模型可达几千像素),把下面的「调用记录」压到只剩十几像素,「收起」按钮和分页器掉到屏幕外,整个抽屉没法用。
- **现在**:
  - 展开后的模型列表是一个**有高度上限的滚动区**,多出来的模型在列表里滚动。上限随窗口高度变化(窗口矮时让给下面的调用记录,窗口高时封顶,再矮也不会被压成一条缝)。
  - 「收起」按钮留在滚动区外面,列表再长也始终点得到。
  - 调用记录区有最小高度;窗口矮到连最小高度都放不下时,整个抽屉可以滚动,不会溢出屏幕。
  - 展开后的滚动区可以用键盘聚焦并带有名称,读屏软件能识别;滚到头不会带动背后的页面。
- **实测**(62 个模型展开,真浏览器量版面):窗口高 700(应用最小高度)/ 900 / 1080 时,「收起」按钮和分页器都在屏幕内,调用记录区分别约 111 / 191 / 306 像素高;修复前 900 高的窗口里这块只有 16 像素,按钮在屏幕外。

## 修正:使用明细「消费合计」的口径说明

- **现象**:汇总卡片写的是「消费合计（不含退款）」,看起来像 Seedance、万相这类视频任务失败退回的钱没有被扣掉。
- **实际**:任务失败时,后端不另写退款行,而是把那一笔原消费记录改成「已取消」并把金额记为 ¥0,汇总是把消费记录的金额加起来,所以**失败任务退回的钱已经不在合计里**。「不含退款」是说反了。
- **现在**:标题改为「消费合计」,下面小字「失败任务退款已扣除」;鼠标悬停有一句说明。明细列表里原有的「已退款」标记和「本页 N 笔退款」不变。
- **例外**:Midjourney 和个别旧任务的退款是单独一行「退款」,**不在**合计里,悬停说明里写明了,以列表里的标记为准。
- **没有改后端**:所以没有「这段时间一共退了多少钱、几笔」这样的区间合计;要加的话需要后端汇总接口新增字段。「请求次数」仍把已取消的任务算作一次。

## 还没覆盖的地方

- **登录取消那条修复没有在真机上由我复现或验证过**:单元测试覆盖了取消、重复发起、超时文案、错误态退出和 `Esc`,但这个问题 8 月实机出现过,真实浏览器授权流程里的表现需要你自己点一遍。
- 使用明细的版面验证是在浏览器里用组件渲染出的页面量的,没有在 Electron 真窗口里逐像素量过;窗口低于应用最小高度(700)的极端情况只做了测量,没有设计专门的布局。
- 「消费合计」的结论(失败任务原地取消、金额记为 ¥0)来自后端代码和今天、近 30 天都没有独立退款行的实测;我没有在真实数据里见到过一条被取消的记录,有真实的失败任务时请对一下。
- 使用明细展开态的高度上限里「其余固定部分」按当前布局估成约 31rem;以后如果这块抽屉增减了固定内容(比如加了新的提示条),这个数要跟着改。
