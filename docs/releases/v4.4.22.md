# v4.4.22 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.21

修复 + 一个新技能:参考图不再因体积发不出去、人像库导入变快、多镜任务多了一张能看的分镜表。

## 带参考图出图不再被体积卡住

MCP 出图时,本地参考图此前是整张转成 base64 塞进请求体,大图直接把请求撑爆
(`400 url is too long`)。现在和批量页、视频生成一条口径:**原图直传 COS 换一个 https 地址**
再发出去,失败才回落压缩 base64。Gemini / nano 这类明确偏好内联的模型不受影响,仍走 base64。

顺带修了引用白名单:跨机器打开旧会话、或引用的附件已被 7 天清理删掉时,不再硬拦整条发送,
而是跳过失效引用并提示;越界但存在的路径仍然拒绝,安全边界没动。

## 人像库导入变快,缩略图不再空白

上游的素材导入是**异步**的——返回那一刻只有一个行 id,真正的 `assetId` 要等它处理完才出现。
我们此前在导入后立刻查一次列表,查不到就报「未解析出可引用 assetId」,还把这个过程卡在
「准备素材」阶段前面,所以又慢又刷警告。现在导入挪到提交之后的后台并发跑,查 assetId 改成
退避重试等它就绪。

缩略图那边是上游的限制:走远程 URL 导入的素材它不去下载,`previewUrl` 恒为 null——而大图必须
走 COS,所以永远拿不到上游预览图。现在导入时把我们自己传的那份 COS 地址记在本地,列表出口
用它补位。**存量的老素材不会自动补上**,只对此后导入的生效;加载失败时也不再留空白,显示占位图。

## 新技能:shotlist-builder(剧本 → 逐镜生产表)

多镜任务此前的产物是一棵 Markdown 目录树,给人看要挨个开文件。新技能补的是那张总表:
剧本拆成镜头行(景别 / 运镜 / 动作)→ 按 4–15s 分组成 Seedance 提示词 → 落成一个自带搜索、
景别筛选和逐条 Copy 按钮的单文件 HTML。

它的加载姿态和 `sd2-pe` 一样是自动的:**有跨镜/跨图连续性就在场**(不止一个镜头、一板卡片、
一个系列、同一角色跨多张图),不需要你说「分镜表」。**手里没有剧本也会主动问**——在工作台上
说「想做个赛博朋克短片」时,它会带着选项问「讲什么 / 几镜 / 谁反复出现 / 规格」,把镜头表问
出来再建卡,而不是让你一张一张现编。

随 `catimation-storyboard-pro` 插件交付。另外两个多角色场景的实用点也在里面:写提示词前先画
一张俯视空间图(米制距离、谁遮挡谁、视线朝向)让你确认;运镜按焦点人物的情绪挑,并且能在一个
长镜头里随表演节拍分段变化。

## Right.Codes 可选 `gpt-5.5-openai-compact`

网关实际售卖的 `gpt-5.5-openai-compact` 不在 Codex 自带的 `model/list` 里,所以模型选择器
一直看不到。本版把它加进 Right.Codes 标准通道的**附加目录**(不影响其它 GPT 动态发现),
并配上与 `gpt-5.5` 一致的 272K 上下文与 Right.Codes 上过滤 `max` reasoning 的策略。

## 运镜知识库不再被 `rerank_top_n` 401 打挂

`search_cinematography_kb` 在传 `top_k` 时会同时塞 `dense_similarity_top_k` 和
`rerank_top_n`。百炼 Retrieve 当前拒绝后者(`field not allowed in agent_config override`),
整次检索直接 401。本版去掉不兼容字段,只保留 `dense_similarity_top_k`。

改的是打包进应用的 `resources/cinematography-kb-mcp/index.js`;本地若还在用
`~/.codex/config.toml` 指到别的脚本路径,需要那份脚本同步去掉该字段,并重启 Codex/MCP
进程后才会生效。
