# v4.9.32 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.31

## 概述

两件事:① 默认出图渠道改为 **腾讯 GPT Image 2.6 Sunburst**(`custom-model-og-v2.6-s`);② 腾讯 GPT Image 2.6 现在可以做**局部(mask)重绘**和**灯箱擦除**。

## 变化

- **默认出图渠道 → 腾讯 GPT Image 2.6 Sunburst。** 只影响**从没手动选过出图渠道**的用户,以及 agent 出图时没点名渠道的情况;已经手动选过渠道的用户保持自己的选择。默认值之前是腾讯 image2(`custom-imagemodel-gt`),它仍在「常用」里(排第三)。「常用」列表现为 7 项:Seedream 5.0 Pro、**腾讯 2.6 Sunburst(默认)**、腾讯 image2、2.5 Flare、2.5 Sunburst、Nano 2.1、万相 2.7 pro;2.6 Flare 放在「更多 · GPT Image 系列」。
- **2.6 支持 mask 局部重绘。** `custom-model-og-v2.6-f`(Flare)、`custom-model-og-v2.6-s`(Sunburst)带遮罩图编辑时不再被早失败拦下,走和 2.5 相同的 `/v1/images/edits` JSON 形状(`images:[{image_url}]` + `mask:{image_url}`)。
- **灯箱擦除沿用当前渠道。** 用户当前选的是 2.6 时,擦除继续用该渠道,不再被悄悄换成 2.5 Sunburst。
- **MCP `generate_image` 说明与 `catimation-image` 技能同步**:默认渠道写成 2.6-s、点名 2.6 可用于 mask / 擦除。为了不超过 Codex 工具 schema 的 16384 字节预算,压缩了几处重复说明(没有删参数)。
- 渠道面板、选择器里 2.6 的说明文字不再带价格提示。

## 注意

- **2.6 按 token 计费,同档位 token 数约为 2.5 的 4 倍**(实测:`-s` 1024² low 一张约 ¥0.166;`-f` 一次擦除约 ¥0.222)。默认渠道换成 2.6-s 后,从没选过渠道的用户每张图的费用会比以前高。给 agent 的指令里仍保留「同档位比 2.5 贵、一次做对、别无谓重试」的纪律,界面里不再提示。
- 本版没有改 2.5 的任何行为,也没有改生成页的默认模型(那是另一项设置)。
- 合并后 `catimation-image` 的 SKILL.md 变了,插件市场的 `catimation-core` 需要随版再发布一次(1.0.36)。

## 已验证

- 真实调用 1(2026-11-06,生产网关,`custom-model-og-v2.6-f`,1024² low,14.4 s,mask 编辑):遮罩外每通道平均差 1.61、仅 0.06% 的像素差超过 40(基本原样保留);遮罩内黄色像素 16278 → 0(被重绘掉);额度 110980 ≈ ¥0.222。
- 真实调用 2(2026-11-06,生产网关,`custom-model-og-v2.6-s`,1024² low,文生图):HTTP 200,21.3 s,16,627 token,额度 83,135 ≈ ¥0.166,返回 `url`。
- 相关目录(`agent-chat` + `services/api` + `src/main/mcp` + `src/shared` + `firstPartySkills`)的单元测试通过,新用例(默认渠道、摆放、无价格提示)在旧源码上先红;`typecheck:ci`、`skills:gen:check`、`audit:skill-arch` 见 PR 检查。

## 还没覆盖的地方

- **mask / 擦除只实测了 `-f`(Flare)**。`-s`(Sunburst)与它同渠道、同适配器,但 mask 编辑没有单独调用过;`-s` 只验证了普通文生图。
- 每项只有一次真实调用,没有多次采样。
- **默认渠道切换没有在安装包 / 真实窗口里走过**(生成页、批量页、Codex 出图面板、灯箱擦除的界面流程都没看过;上面的真实调用是直接打生产网关)。
- MCP `generate_image` 的 schema 仍贴着 16384 字节预算,余量很小,下次再加渠道说明会先被 `toolSchemaBudget` 守卫拦住。
