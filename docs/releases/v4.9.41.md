# v4.9.41 发布说明

## 概述

两件事:

1. **对话里图片很多时不再卡死**(#458):打开线程、收起线程侧栏、滚轮滚动,在一屏之外还有几十上百张图的对话里不再把整个窗口冻住;缩略图位置也不再去加载原图。
2. **Codex 页模型选择器加入 Qwen 4 Max**(#459,`qwen4-max`,走 Miau 网关的千问通道)。

## 变化

### 对话里图片很多时(#458)

- **只在滚到可视区附近(上下各 800px)才加载缩略图和视频封面**。真窗口量测(60 条消息 × 4 张 = 240 个缩略图):打开线程时发出的缩略图请求从 240 个降到 48 个;图还在加载时连续开关侧栏 4 次,最长一帧从 3183 ms 降到 217 ms。
- **主进程缩略图限流 + 缓存**:同时最多 4 张在处理,同一张图的在途请求合并,结果放进 32 MB 封顶的内存缓存(文件变了自动失效,失败不缓存);图片改为先用 sharp 缩小,sharp 解不了的格式(如 BMP / ICO)才退回系统缩略图提供者。
- **缩略图位置不再加载原图**:带签名的链接、别家 CDN 的图、`data:` 内联图,原来会直接把整张原图交给图片控件;现在改由主进程下载后缩小再显示(只收 https 与 `data:image`,过一道本机 / 内网地址检查)。主进程取不到图时显示「加载失败」占位,不会退回原图。真窗口模拟下:渲染进程直接请求原图 0 次,主进程同时代取最多 4 个,图片控件拿到的全是缩小后的 `blob:`。
- 点开放大、复制、下载仍然使用原图。

### Qwen 4 Max(#459)

- Codex 页模型选择器新增 **Qwen 4 Max**(Extra High 档),排在千问组最前面;apiyi / rightcode 两个网关都走现有的千问通道。
- 生产网关的价目表里确认有 `qwen4-max`(与 `qwen3.8-max` 同形:价格倍率 5 / 补全倍率 3 / 缓存倍率 0.05,折算后与官方页 ¥10 / ¥30 / ¥0.5 每百万 token 一致)。
- 上下文窗口沿用千问行的保守默认(200K),1M 仍是「实验」选项;官方页写 1M,但没有对网关实测过超长请求,没有抬高默认值。

## ⚠️ 行为变化(请知悉)

- **离可视区很远的图,猛甩滚动时会先是空底框**,滚到附近才加载。
- **所有非 COS 的 https 图(包括别家 CDN 自带的小缩略图)现在都经主进程下载并缩小**,多一次主进程往返;防盗链或需要 cookie 的地址以前可能靠浏览器直接显示,现在会显示「加载失败」。
- **主进程多占最多 32 MB 缩略图缓存**;缓存只在内存里,重启后从零开始(重新打开线程时只为可视区附近约 48 张各缩小一次)。
- **没有登记 Qwen 4 Max 的真实上下文窗口与推理档位**:选它时界面显示的是千问通用默认。

## 还没覆盖

- **没有用真实令牌向网关发过一轮 Qwen 4 Max 对话**:工具调用往返、Responses 的 namespace 桥、流式输出、用量回传都没跑;只对价目表确认过模型存在。思考模式(`enable_thinking`)经网关的行为没验证;视频原生输入沿用现状(只有 `qwen3.8-omni-flash` 支持);理解类工具的「旗舰」仍是 `qwen3.8-max`。
- #458:没有人手点过;性能数字在 dev 渲染进程里量的(没走安装包),只当方向。第二部分(远程图)用的是模拟网络的 `net.fetch`,没有用真实 COS / 真实签名链接 / 开代理的环境。实时出图那一刻的 `data:` 内联图只有单测,没在真窗口里用真实出图走一遍。远程图的内网检查只看地址字面量、不解析 DNS。`MediaTile` 对用户附件图的透明度探测(`probeImageAlpha`)没动,仍会加载原图。远程图那条路比本地缩略图更「噪」:挂载时有 130–320 ms 的长任务,猛甩后只加载了约一半。
- COS 持久化缩略图(`.thumb512.webp`)、数据万象实时缩略这两条路径本版没动,也没对真实 COS 验过。
- 只在 Windows x64 验证;macOS / Linux 没测。
- 没测 NSIS 安装包的安装 / 覆盖升级 / electron-updater 自动更新,只测了构建产物;这部分由发版流程的三道闸与 Authenticode 校验兜底。
