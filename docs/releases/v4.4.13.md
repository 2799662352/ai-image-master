# v4.4.13 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.12

## 概览

紧接 v4.4.12 的修复版:上一版新加的 Right.Codes Claude 通道用的是厂商的旧域名,
该域名在国内网络已被屏蔽,导致国内用户选 Claude 后**一个错都不报、就是干等**。
本版把该通道换到厂商公告的新域名。

## 修复

- **Right.Codes 的 Claude 通道换到新域名**:厂商已公告原域名 `right.codes`
  在国内网络被屏蔽,新域名 `rightapi.ai`,API 路径与行为不变。屏蔽的表现不是
  被拒绝而是连接一直挂到超时,所以症状是无声卡死——界面上没有任何报错可看,
  比报错更难判断。同网关的另外两条通道(GPT-5.5、Grok)本来就在新域名上,
  所以只有 Claude 这一条受影响。

  使用 API Yi 通道的 Claude 不受此问题影响,不需要任何操作。

## 验证

- 新域名实测:`/claude-sale/v1/models` 726ms 返回 200,
  `/claude-sale/v1/messages` 2972ms 返回 200 且回显 `claude-opus-5`。
- 旧域名在开着加速器的机器上仍然可用——正是这种"开发机通、用户机不通"的
  差异让该缺陷躲过了发版前的验证,已把这点写进代码注释,避免下次照着开发机的
  观感把结论定反。
- 相关三个测试套件 101/101 绿;Quality Gate 七项检查全绿;
  typecheck 债务闸 0 新增。

## 已知问题

- 另有一个与本次域名无关、同样表现为"无声卡死"的缺陷已定位但未修:两次
  后台服务重启若在极短时间内接连发生,两个进程会抢同一个本地端口,后启动的
  那个会因端口占用直接退出,界面同样只能干等。触发条件是短时间内连续切换
  模型/网关。下一版修复。
