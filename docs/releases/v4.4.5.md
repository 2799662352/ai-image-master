# v4.4.5 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.4

## 概览

本版接入火山豆包 **Seedream 5.0 Pro** 出图渠道(经 Miau API 网关,
OpenAI 兼容端点),聊天 composer 与 Codex agent 全链路可用;并修复
「模型自带分辨率映射表时,不支持的档位会回落通用表发出无效尺寸」的
边界 bug。

## Seedream 5.0 Pro 出图渠道

- 模型注册:`doubao-seedream-5-0-pro-260628`,文生图 / 图生图 /
  多图融合(最多 10 张参考图),10 比例 × 1K/2K 像素档(按官方
  映射表),仅单图输出。
- 聊天渠道选择器新增第 6 项「SD5 / Seedream 5.0 Pro」;渠道标记
  Miau-only,出图请求自动固定走 Miau API 站点,无需手动切站点。
- MCP `generate_image` / `generate_images` 的 `model` 枚举加入新渠道;
  agent 在用户说「seedream / 即梦 / 豆包」或需要多参考图融合时显式
  选它,平时仍跟随用户 composer 渠道(默认 VIP)。
- `catimation-image` skill 与 `/gen-image` 命令同步渠道清单
  (5 → 6),经单一真源生成链更新首方 skill 与插件市场
  (catimation-core 1.0.19)。
- 参考图契约:单张发顶层 `image`,多张发 `image`(首张)+
  `images`(全部);COS URL 直传不内联 base64;Pro 不支持的
  `sequential_image_generation` / `stream` / `n>1` 从源头不发。

## 尺寸解析边界修复

- `getImageSize` 优先读模型自己的 `resolutionMap`(补齐通用表缺失的
  4:5 / 5:4 档位)。
- 模型配了映射表但请求档位缺失时(如 5.0 Pro 无 4K、SeeDream 4.5
  无 1K),收敛到模型 `defaultResolution`,不再回落通用硬编码表——
  避免把上游不支持的像素尺寸发给网关。既有模型(SeeDream 4.5 /
  万相 / gpt-image-2 系列)映射行为不变。
