# v4.9.40 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.39

## 概述

两件事:

1. **视频工作台剧栏再拉长**(#455):剧栏高度改成接近整屏,底部入口浮在可视区底部,不再空出一大块;剧多了在栏内用滚轮滚。
2. **对话里助手正文嵌的图片可以放大、复制、下载**(#456):之前正文里的图点了没反应、复制不了;本地盘符路径的图(如 `Q:\…\总览.jpg`)还会显示成裂图。

## 变化

### 视频工作台剧栏

- 剧栏高度 = 窗口高度 − 24px(保底 360px)。上个版本滚动时恒定、但页面在顶部时只有约 564px(861px 高的窗口),底部空着约三分之一;现在 861px 高的窗口里是 837px,底部空白 12px。
- 底部「导入 / 导出 / 云备份 / 回收站」一行改为粘在剧栏底部,页面在顶部时它也浮在可视区底。
- 剧多到放不下时,在栏内用滚轮滚;滚动页面时剧栏大小不变。
- 实现从 JS 量高改成纯 CSS,删掉了 scroll / resize / ResizeObserver 的量高逻辑。

### 对话里的图片

- **点击正文里的图 → 打开大图灯箱**,和生成图卡、附件卡一致。
- **悬停出「复制 / 下载」**:复制到系统剪贴板(粘贴到别的程序是图),下载弹「另存为」。大图灯箱顶栏同样有「复制 / 下载」。
- **附件区缩略图的「下载」对本地图可用**:之前对本地图静默失败。
- **能显示的写法**:`https://…`、盘符路径(反斜杠或正斜杠,路径带空格 / 中文时需写成 `<C:\a b\c.jpg>`)、`file:///…`、`data:image/…;base64,…`。读不到的图显示「(图片无法加载)」占位,不会一直转圈。
- **正文图只在靠近可视区(上下各 800px 内)时才读盘**:一次对话里有几十张 1 MB 多的大图时,不再挂载就全读。真窗口量测(2336×1460、1 MB 的本地图):120 张时第一张出来从约 8.2 秒降到约 0.9 秒,40 张从约 2.4 秒降到约 0.7 秒;滚动帧率本来就正常(约 60fps)。
- 主进程的「复制图片 / 图片另存为」现在认得 `local-file://`、`file://`、盘符路径、https、`data:` 五种来源(远程和内联有大小上限,https 非 2xx 会拒绝并报原因)。

## ⚠️ 行为变化(请知悉)

- **图片放大 / 复制 / 下载只对正文里按图片语法写的图生效**(`![说明](地址)`)。路径里有空格又没用 `<…>` 包起来时,Markdown 本身不会把它当图片,这是模型输出格式问题,没处理。
- **读过的图不会在滚远后释放**:进入范围后,这张图的内存一直保留到该消息卸载。长对话里一直往上翻,被看过的图都会留着。
- **同路径的文件被覆盖重生成后,对话里可能仍显示旧图**(缓存按路径),与 Codex App 的 [openai/codex#24446](https://github.com/openai/codex/issues/24446) 同类,这版没处理。
- 没到范围的图先显示一块小骨架,图读出来后高度会变,滚动区会有布局位移(Chromium 滚动锚定会兜住大部分,没专门量)。
- 剧栏:页面在顶部时,剧栏底部边框在折叠线下(入口仍浮在可视区底);右侧内容很短时页面会被撑到整屏高。

## 还没覆盖

- 没有人手点过;性能数字每个场景只跑了 1–2 次,且在 dev server 渲染的窗口里量的(没走安装包),只当方向。**内存没有量出改善**(渲染进程工作集波动大于差异),不要当成收益。

- 没测 NSIS 安装包的安装 / 覆盖升级 / electron-updater 自动更新,只测了构建产物;这部分由发版流程的三道闸与 Authenticode 校验兜底。
