# v4.9.44 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.43

## 概述

三件事:

1. **别的对话生成的图 / 提问卡不再出现在当前打开的对话里**(#468、#469)。
2. **Codex 页的模型选择器新增 Gemini 4 Neon / Carbon / Argon**(#470)。
3. **Codex 内核 0.169.0 → 0.170.0**(#467),不需要适配,没有用户可见变化。

## 变化

### 对话串台(#468、#469)

用户报告:在「人物图」对话里看到了另一个对话生成的场景图。那台机器的埋点里,出图 1,512 次有 718 次没有带发起对话的线程;以前这种调用会被算到「当前打开的对话」头上。

- **认不出是哪个对话发起的调用,不再猜**(#468):活照干、结果照存(历史记录 / 作品库、磁盘上的文件),但不进任何对话;每 10 分钟最多一条全局提示,告诉用户去历史记录 / 作品库找。`ask_user` 这种情况下不弹卡片,立刻回「没人看到这个问题」。
- **认得出的尽量认出来**(#468):主进程给每个 MCP 工具都带上调用方线程(以前画布、导演台、历史、界面、人像库的大部分工具根本没往下传),并按「自己的线程(当前 / 子代理 / 被换下的旧线程)→ 祖先线程 → 数据库反查」认领。
- **每条 Codex 线程连回 app 的连接,从建立起就带着所属对话**(#469):上面几步都认不出时,按连接上带的对话归属。只认本进程亲手下发过的对话 id;对话删除立刻撤销。
- **回执说实话**(#468):没显示在任何对话里的结果,回给 agent 的是「没有显示在任何对话里 + 保存路径」,不再是「用户已经看到了」。有归属的调用,回执文字逐字节不变。
- 埋点多了几个字段(`thread.via` / `thread.attribution` / `codex.thread.id` / `codex.thread.ancestors`),都是随机 id,不含用户内容,只在不是最普通的情况下才写。

### Codex 页新增 Gemini 4(#470)

- 模型选择器多一个 **GEMINI** 分组,排在 DeepSeek 与 Grok 之间:Gemini 4 Neon、Gemini 4 Carbon、Gemini 4 Argon。
- 走 Miau 网关(平台余额或自填 Miau Key),与 Grok (Miau) 通道同一套做法。
- **没有思考强度档位**:网关目前不会对 Gemini 4 下发思考强度,模型按自己的缺省档跑。
- 前提在网关侧:2026-11-20 网关把这三个模型所在的渠道改成了 Gemini 型,Codex 用的 `/v1/responses` 才通(改之前一律 400)。

### Codex 内核 0.170.0(#467)

锁文件 5 个哈希与官方 release 资产一致;协议 schema 479 个文件、新增 0、删除 0,方法集相同。app 不需要改代码。

## ⚠️ 行为变化(请知悉)

- **认不出发起对话的结果不再出现在任何对话里**,改成一条提示 + 去历史记录 / 作品库找。如果某台机器上认不出的比例仍然很高,用户会觉得「图少了」;这时新埋点字段能直接说出是哪类线程。
- 认不出发起对话的 `ask_user` 不再弹卡片;这类调用启动的工作台批次跑完后不再有完成推送。
- **Gemini 4 目前很慢、偶发失败**:2026-11-20 下午实测,一句「回复 ok」要 31–208 秒,另有 429「当前分组上游负载已饱和」和 504。同一时刻走别的渠道的 DeepSeek 是 1 秒 —— 慢在这条渠道的上游(上游文档写明首发时段有「数分钟级排队」),不是 app 卡住。
- 本版四个改动都没有改技能 / 插件文件,插件商城与技能商城不需要随版发布。

## 还没覆盖

- **用户机器上那 718 次没带线程的出图到底走的哪条路,没有证据。** 本版能保证的是「认不出的不会再落进别的对话」;其中有多少会被归回正确的对话、有多少会变成「不显示在任何对话里」,要看发版后的新埋点。
- **没用真实 Codex 复现出「app 认不出的子线程」**:真实子代理在窗口里是被原有的第一步认出来的,#469 新增的那一步只在脚本模拟的连接上触发过,目前是兜底。
- **没在 app 里用真令牌跑过一轮 Gemini 4 的 Codex 对话。** app 里多出来的环节(MCP 工具摊平、Codex 自己拼的请求体、十几个带复杂 schema 的工具、记忆请求、换通道后重启 Codex)在这条通道上只有单测。
- Gemini 4 的 Argon 与 Neon 没拿到一遍干净的「连续多步工具到最终回答」:各有一次响应头 200 后连接中断,当时测试机到网关入口的握手也在偶发失败,原因没查清。上游排队到几分钟时,Codex 会不会当成断流去重试,没实测。
- Gemini 4 没测:并行工具调用、图片 / 视频输入、超长上下文。上下文窗口没登记(按未知模型的 200K 处理)。
- 批量出图、视频、音频、画布 / 导演台导出在「认不出发起对话」时的表现只有单测,没在真实窗口里跑。
- Codex 0.170.0 没用真实令牌、真实模型跑过对话 / 出图 / 视频;给模型的工具次序变了,对上游提示缓存命中率有没有影响没量。
- 只在 Windows x64 验证;没测 NSIS 覆盖升级 / electron-updater,只测了构建产物,这部分由发版流程的三道闸与 Authenticode 校验兜底。
