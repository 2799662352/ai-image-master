## 概述

**修「两个对话里生成的图 / 导出物串台」。** 现象是看你停在哪个对话,别的对话的东西就落到哪个对话里。排查下来这不是一个点,而是三个互相独立的入口,都是同一类毛病:异步结果回来时,去「当前活动对话」里写,而不是写进发起它的那个对话。本版一并修掉。

## 变化

- **画布导出 / 导演台工具按发起对话落附件**(#439):`canvas_snapshot` / `get_canvas_image` / `get_canvas_video` / `save_snapshot` / `canvas_focus_region`,以及导演台的 `capture` / `record` / `scene` 导出。导出物是对话的附件、虚拟视口也按对话分;以前取的是「此刻活动的对话」,现在优先取发起这次工具调用的对话,取不到才回退。
- **发消息后切走,不再被抢回**(#440):发送要等主进程受理回合才返回(排队、新对话的创建、附件落盘),这段时间里你点去别的对话很正常。以前返回时会无条件把活动对话改回发送方,屏幕上还是你刚点开的那个对话的消息,之后发送方的所有事件和出图气泡都写进了你正在看的那个对话。现在判断「你是否还停在发送方」:已离开就只更新发送方自己名下的状态,不碰你正在看的视图。
- **新对话按发起它的那次发送认领线程**(#441):多个新对话先后在途时,以前靠「当前没有线程且在跑」猜哪个线程是自己的,会认错。现在发送带一个客户端 id,主进程原样盖在对应的 `thread_created` 上,渲染端按 id 认领。

## ⚠️ 行为变化(请知悉)

- 在**新对话**里发消息、还没等到受理就切走:这条用户消息现在会补进它自己的对话(按代码推断,以前从侧栏点开会看到没有提问的回答,没有在窗口里复现过);如果这次发送最终失败,会弹一条全局提示,而不是把错误挂到你正在看的对话上。
- 已有对话在你切走后发送失败:失败标记和重试快照留在那个对话里,你回去能点「重试」。
- 没有新增界面,也没有改动数据库。

## 还没覆盖

- **没有在真实 Electron 窗口里跑过「两个对话并行」**:上面全是真实 store / 真实 `AgentManager` + 假后端的测试,所以不能断言你遇到的每一次串台都是这三条之一。升级后如果仍有,请告知串台出现在**聊天气泡 / 附件面板 / 画布**哪一处。
- 主进程反查不到线程(刚创建 / 未登记 / 子代理先于父级通知)时,agent 工具请求仍回退到当前活动对话,只有 `console.warn`。这是 #408 留下的缺口,未动。
- 没有引入「草稿 key」(新对话从第一毫秒起就用客户端生成的 key 存状态,拿到线程 id 后再映射)。`threadId` 在渲染端和 IPC 里到处被当真实线程 id 用,改成双键要碰每个消费者;三个 PR 已经把离场新对话的气泡、认领归属、运行状态落到正确位置,评估后收益不够抵风险。
- 画布本身是全局唯一一块,内容跨对话共享是设计,不是 bug。
- 本机跑 `directorMmd.test.ts` 因 `node_modules` 联接被 vite fs 限制拒绝而失败,CI 上通过。
