# v4.4.26 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.25

这一版都在治「AI 看着像在干活、结果不是你要的那个」——参考图错位、角色越画越不像、
批量出片互相抢带宽。

## 批量出片不再一拥而上

工作台一次启动十几张卡时,每张卡的参考图、参考视频、参考音频会同时往云端传,几十个
上传挤在一个瞬间。互相抢带宽 → 一部分超时 → 各自重试三次 → 再来一波。

现在上传排队走,同时最多四个在飞,第五个等前面完成。**总量没变,反而更快** ——
不再互相抢、不再因为超时白重试。这个数字与界面上传那条路一致(实测四个足够打满
网络,瓶颈在云端单连接带宽,开更多只是让更多人抢同一根管子)。

单张卡内部也从「一张传完再传下一张」改成一起传:六张参考图的卡,准备阶段明显变快。

## 参考图的位置就是编号,不会再错位

提示词里写「图1 的人穿 图2 的衣服」时,「图1」指的就是你传的第一张——按顺序对应,
不是按文件名。这一版修了两处会**悄悄改变这个顺序**的地方:

**一张读不出来时不再静默跳过。** 传了三张、第二张读取失败(文件被移走、格式不支持),
以前会返回剩下的两张继续生成——于是「图2 的衣服」指向了原本的第三张。画面看着像那么
回事,没有任何提示。现在会明确告诉你是哪个文件读不出来。

**重复的参考图不再被折叠。** 「图1 与 图3 是同一个人」这种写法,以前会把重复项去掉,
数组变短,后面的编号全体前移。现在传几张就是几张。

内部并发化时也锁死了这条:先把所有素材准备好,再按你传入的顺序拼装,与谁先传完无关。

## 看图不再只看一张然后猜

九宫格质检、一组分镜、一板卡片的产物 —— 以前为了不撑爆上下文,只看「代表性的一张」,
其余靠猜。这是拿信息换预算。

现在超过五张就走并发理解:每张图交给 qwen 看,回来的是文字结论,图本身不占主对话的
空间。九张全看,而不是看一张猜八张。

**结论会落在图片旁边**:`<图名>.vision.json`(给 AI 读)和 `.vision.md`(给你读)。
下次再碰到同一张图,先看这份结论——比图新就直接用,图重生成过就作废重看。跨会话、
跨天接着做的人不用重来一遍。

## 角色跨会话不用重新描述

这一版给出图补了两层一致性:

**同一批图里不漂** —— 有参考图时先把它拆成脸型 / 体型 / 服装 / 特征标记四段锚点
(锚点写得太简略正是形象漂移的根因),组图的每一张都带全,而不是第一张写详细、
后面写「同一个人」。

**下次、下个会话还是同一个人** —— 会复用的角色出完图存进人像库,下次说「还是上次
那个人」时直接找回同一份素材,而不是凭聊天记录重新描述一遍。判据很简单:这个角色
会不会再出现第二次。

出图的提示词也统一按七字段顺序拼装(主体动作 → 角色引用 → 场景 → 镜头 → 光照 →
构图 → 风格),丢字段是出图不稳的直接来源。
