# v4.7.0 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.6.0

## 概览

这一版只有两件事:聊天里的 diff 卡片重做,以及镜头语言知识库那个 MCP 起不来的修复。

抬到 4.7.0 而不是补丁位,是因为 diff 卡片的呈现方式整个换了 —— 它不再是「一个文件
摊开一面三千多像素的墙」,而是每个文件一行、想看哪个点哪个。这是每天都会看见的
交互面,不是内部修补。

## 聊天里的 diff 卡片

### 默认收起,一个文件一行

改造前这张卡是分叉的:改 1 个文件时把整份 diff 摊开(实测能到三千多像素高,滚半天
滚不完),改 2 个以上反而一条 diff 都不给、只列文件名,想看内容得跳去右侧并排视图。
同一张卡按文件数量长成两个样子。

现在统一了:每个文件一行,显示路径和 `+N/−N`,点开才看内容。多文件时各行互相独立,
可以只摊开你关心的那个。

### 行号与配色

diff 正文左侧有两列行号槽(旧行号 / 新行号),横向滚动长行时行号钉住不跑。新增行、
删除行、hunk 头各有克制的底色和左侧色条 —— 不是整行高亮,那在长 diff 里会糊成一片。

超过 200 行的 diff 默认截断,底部给「显示全部」。

### 改动进行中就能看见(仅限标准编辑工具)

**这一条有适用范围,先说清楚。**

agent 通过标准编辑工具(apply_patch)改文件时,卡片会在它写的过程中就摊开、跟着新
写进来的行往下滚,写完自动收起。

**但如果模型是用命令行改的文件(比如跑一条 PowerShell 写文件),这一条不生效。**
那种情况下改动来自另一条链路 —— 回合结束时对比工作区快照 —— 按构造只能在整轮结束
后一次性出结果。用不同的模型和网关,走哪条路是不一样的:实测自建网关配 Qwen 时,
模型全程用命令行改文件,不走标准编辑工具。

让命令行那条路也能实时,是下一步的事,设计已经写在
`docs/superpowers/specs/2026-08-17-file-change-channels-and-live-observed.md`。

### 顺带修掉的

- 同一份 diff 在特定时序下会被拼两遍、`+N/−N` 翻倍
- 流式期间文件路径从相对变成绝对时,整行会被重建 —— 你手动收起的那一行会自己弹开
- 三处性能问题:两处随 diff 长度平方增长的重复扫描,以及每帧重新解析整份 diff 并为
  每一行分配对象。都发生在你盯着卡片看的那段时间里

## 镜头语言知识库(MCP)起不来

`cinematography_kb` 在部分机器上报「connection closed: initialize response」。

根因是 `config.toml` 里存着一条指向**旧安装目录**的路径。装到新位置之后那条路径就
失效了,而原来的修复逻辑只认「格式不对」,认不出「路径指向了一个不存在的地方」。

改成和 catimation 同样的做法:**每次启动现算路径,不依赖配置文件里存的那份**。
同时把配置文件里的陈旧条目也一并修正,免得别的客户端读到坏值。没装 Node 的机器
照样能用 —— 它会用应用自带的运行时。

## 已知限制

- 命令行改动仍然只在回合结束后出现(见上文)
- 改动进行中的行号槽可能是空的:上游在流式阶段发的 hunk 头不是标准格式,拿不到行号。
  回合结束收到完整 diff 后恢复正常
- 「本轮改动了 N 个文件」里带「命令行」标记的行**不保证都是 agent 改的**:同一时间
  窗内你在别的编辑器里的改动、后台进程写出的产物,都可能落进来。这是读磁盘方案的
  固有代价,标记和文案如实交代,不混进来假装同样可信
