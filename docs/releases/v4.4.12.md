# v4.4.12 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.11

## 概览

本版一条主线:**Claude 可以直接用了**。`claude-opus-5` / `claude-sonnet-5` /
`claude-fable-5` 在现有模型选择器里与 GPT、Grok 平级可选,捆绑的 codex
二进制不动一行。同批修掉两个只有接上 Claude 才暴露出来的真问题:token
用量少报(缓存读写算不出来)、跨会话记忆的开关被线程内路由绕过。

## Claude 通道

codex 只会说 Responses API,Claude 只会说 Anthropic Messages API。中间加一层
本机 loopback 桥做协议翻译,复用既有的 `compatibilityPolicy` 缝线(带穷尽
检查的联合类型,新增分支漏实现会编译失败),Grok 通道走的那条策略一路没动。

两个通道各自的差异都是**实测**定下来的,不是照文档配的:

- **API Yi(`apiyi-claude`)**:三个 slug 都是真路由——`/v1/models` 广告、
  各自回显自己的名字,且不可能存在的对照 slug 被指名拒绝。缓存开着:
  同一段 ~4k 稳定前缀,输入从 3974 降到 2 + 3972 缓存读(读按 0.1x 计费,
  而每一轮都要重发整段对话)。跨会话记忆也留着——同端点供 gpt-5.5,
  记忆的提取/整理交给它做。
- **Right.Codes(`rightcode-claude`)**:`claude-fable-5` 在那边会被静默换成
  `claude-opus-4-8`,所以不在该通道提供——界面上给一个永远不会真跑的模型
  比不给更糟。该池自己插缓存断点(从未发过的前缀、不带缓存标记也照样
  billed 写入并在复发时全额读回),所以我们不再叠加自己的断点。跨会话记忆
  在该通道关闭:那台主机的模型目录里一个 GPT 都没有,记忆管线换不到能产出
  合法条目的模型。

## 同批修掉的两个真问题

- **token 用量少报**:流式回合里,缓存读写此前一律算不出来——占位帧里
  缓存计数是 0,真数只在结束帧落地;而 Anthropic 的"输入"不含缓存部分,
  与我们表盘用的语义正好差了缓存那一段。同一份用量数据喂上下文窗口圆环和
  跨卡成本聚合,所以少报会让人以为"上下文还有余量",缓存则看着像从没生效。
  现在按上游真实计费口径修正后再上报(实测:修前两回合都报输入 2441 /
  缓存 0,修后 3755 / 缓存写 3753 与 3755 / 缓存读 3753)。
- **记忆开关被线程内路由绕过**:关闭跨会话记忆此前是进程级启动开关,只在
  Claude 通道恰好是启动时的激活通道才生效。而同网关的兄弟通道在启动时就
  一起注册好了,从 GPT 切到 Claude 是不重启的线程内切换——开关根本没重新
  下发,Claude 照旧往记忆库里写它那些非法条目。现在改为跟着**线程**走:
  线程绑定到不能写记忆的通道时,单独把该线程的记忆资格关掉。用户自己的
  选择不会被覆盖写掉,线程回到能写的通道时自动恢复。

## 开发体验

- 新 clone / 新 git worktree 第一次发消息不再死在「找不到 codex 二进制」。
  350MB 的运行时不进 git,现在 `dev` 前自动备好:已有则跳过,机器缓存里有
  就硬链接进来(实测 0.9s、不联网),都没有才下载钉住的版本并顺手种缓存。
  缓存放在 git 公共目录下,所有 worktree 共享同一份(N 个 worktree 只占
  一份 350MB)。
