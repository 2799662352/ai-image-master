# v4.4.2 发布说明

> 发布渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 兜底
> 基线版本：v4.4.1

## 概览

本版是跨 Provider 对话稳定性专项：统一网关/通道模型路由落地后,针对
Grok 4.5 与 GPT 系列互切、模型切换卡顿、会话中途静默失联、图片/视频
生成不主动跟进等一批实际使用中暴露的问题做了系统性修复。

## 统一模型路由(网关/通道)

- 设置页不再出现 `API Yi Grok`、`Right.Codes Grok` 独立卡片:Grok 通道
  并入所属网关(API易 / Right.Codes),同一网关只录一次密钥。
- 聊天 ModelPicker 直接列出网关下全部可用模型,按家族分组,xAI(Grok)
  排在 OpenAI 之上;跨通道选择模型时自动切换底层通道并给出轻量提示。
- 模型选择走原子事务:选择、上下文与通道切换统一由协调器仲裁,
  渲染层"模型选择"与"上下文调整"意图分离,不再互相顶掉。

## 跨通道对话连续性

- Grok 线程切到 GPT 通道后可以继续对话:`thread/resume` / `thread/fork`
  显式携带当前通道的 `model` / `modelProvider` 覆盖,不再因持久化元数据
  指向已卸载的 Provider 而报 "Model provider not found"。
- 5.5 与 5.6 互切不再触发不必要的 Codex 重启:上下文窗口仅在与
  Codex 原生元数据不一致时才显式钉扎(context pin)。

## 会话与流稳定性

- `turn/stream` 错误尊重上游 `willRetry` 标志,瞬时错误不再被当作
  终局失败导致主进程与渲染层状态脱节("对话丢状态卡住")。
- 新增流空闲看门狗:Codex app-server 中途静默时主动检测并收尾,
  不再无限等待。
- 兼容代理提高 keep-alive / headers 超时,消除长回合下的 `ECONNRESET`。

## Grok 4.5 通道修复

- 修复 xAI `422 Unprocessable Entity`(untagged enum ModelInput):
  兼容代理剥离输入项中的 null 字段,并对 xAI 家族通道强制启用
  Responses namespace 桥接。
- memories 功能的抽取/整理模型随通道钉扎(API易走 `gpt-5.5`),
  不再在 Grok 专用端点上发出会 400 的 `gpt-5.4` 副请求。

## 图片/视频任务交付

- 渲染进程重载或崩溃时,主进程立即失败所有运行中的图片任务与挂起的
  渲染层工具调用,不再挂满 30 分钟超时。
- `generate_image` / `generate_images` / `generate_video` 的交接横幅
  升级为强制持续轮询指令,模型不再"提交后弃单",生成完成即刻回报。

## 验证

- 主进程 + 共享层回归:104 个测试文件、1242 个测试全部通过。
- 新增测试:流重试(willRetry/watchdog)、渲染层生命周期清理、
  线程恢复覆盖、上下文钉扎、模型路由目录等。
- 端到端诊断脚本实测:Grok 线程切 GPT 通道后 resume 成功并继续对话;
  Right.Codes / API易 Grok 4.5 真实回合正常收尾。
