# v4.3.95 发布说明

> 发布渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 兜底  
> 基线版本：v4.3.94

## 概览

本版完成 Codex 0.144.1 模型设置全链路对齐：模型选择器升级为能力驱动的
Context / Reasoning 面板，普通推理与 Plan 推理解耦；Context 变更会真实重启
Codex、严格恢复当前线程，并在失败时执行一次性回滚。

## 模型与 Reasoning

- 每个真实模型只显示一行，不再把 `gpt-5.4-high` 等 effort 变体伪装成模型。
- 普通 Reasoning 按模型独立记忆，Plan Reasoning 继续使用线程级 Plan 设置。
- Right Code 下 GPT-5.6 Sol 支持 `Max`；GPT-5.5 不显示 `Max`。
- 当前 API Key Provider 不显示未经证实的 `Ultra` 与 `Fast`。
- 旧模型选择偏好自动迁移到版本化存储，不覆盖未来同名真实模型。

## Context 与生命周期

- GPT-5.6 默认 372K；GPT-5.5 / 5.4 默认 272K；未知模型保守使用 200K。
- 所有模型可主动选择实验性 1M，并明确提示 Provider 拒绝、HTTP 413、费用与
  延迟风险。
- 自动压缩阈值统一为 Context 的 90%，移除固定 220K 启动参数。
- Context 应用顺序为：持久化 pending → 重启 → 严格恢复同一线程 → 刷新能力
  → 确认；任一步失败会恢复旧配置。
- Provider 切换、普通发送、steer 与 Context 重启共享生命周期队列，避免旧
  Provider、旧 epoch 或并发请求污染当前线程。

## UI 与错误恢复

- 模型设置面板支持方向键、Home / End、焦点恢复、pending 禁用与读屏状态。
- 回滚失败会保持醒目的手动恢复提示，普通目录刷新不会误清除错误。
- 上下文超出网关限制时会自动在新线程继续，并提示切回模型官方 Context。
- Token 使用率优先采用 Codex 实际返回的窗口，否则使用主进程确认的 Context。
