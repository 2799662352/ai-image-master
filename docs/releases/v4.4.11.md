# v4.4.11 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.10

## 概览

本版两条主线:**上游任务不再被暂时性故障错杀**——四处「一次网络抖动就
丢掉已付费任务」的缺陷修复;以及**生成视频工作台**——撤销/重做栈、
看板 JSON IR(agent 可一次性重构整板)、跨卡成本聚合。另有 Codex 通道
两条如实上报修复,与一批内部质量还债。

## 上游任务不再被暂时性故障错杀

四处同一形状的缺陷——**把暂时性失败当成终局**,且都发生在**已经付费**的
上游任务上:

- **视频轮询错误分类(#127)**:密钥失效(401)、任务不存在(404)这类
  永不自愈的错误,此前会被当成网络抖动重试约 300 次、耗满 30 分钟,
  最后报一句与真因无关的「轮询超时」。现在按 HTTP 语义分流:不可重试的
  立刻如实报错;暂时性的(5xx / 限流 / 网络层)退避重试,并遵守上游
  `Retry-After`;超时收场时带上最后一次的真实失败原因。
- **重启对账不再错杀在飞任务(#127)**:应用重启后接管仍在跑的任务时,
  预探失败此前一律判定「任务已不存在」并把卡片打成失败。现在只有 404 /
  401 才算真没了,网络抖动或上游 5xx 照旧接管——那些任务还在跑、
  钱已经付了。
- **智能去字幕轮询容错(#128)**:轮询期间一次网络抖动或 STS 换票失败,
  此前会让一个腾讯侧还在跑的抹除任务在界面上永久失败(任务队列不重试)。
  现在退避重试,成功一轮即清零,连续失败到上限才如实认输。
- **结果转存补重试(#129)**:转存历史桶失败会退回只活 30 分钟的签名 URL
  ——等于半小时后用户彻底丢结果。下载半程补一次重试(签名过期 / 对象
  不存在不重试),与已有的大媒体下载惯例一致。

## 生成视频工作台

- **撤销 / 重做(#114)**:工具条按钮 + `Ctrl+Z` / `Ctrl+Shift+Z`,
  50 步上限。步边界按「改动目标 + 空闲超时」合并,连续打字算一步而不是
  每个字符一步;正在渲染的卡片不会被撤销复活,在飞任务不会被撤销删掉。
- **看板 JSON IR(#112、#116)**:agent 可导出整个工作台为声明式 JSON、
  改完一次性写回,不必逐卡调五个细粒度工具。并发令牌拆成**两级**——
  结构令牌管建页/加卡/排序,每卡另有独立版本号管提示词;这样用户在
  A 卡打字不会废掉 agent 对 B 卡的整份回写,冲突逐项报告而非全盘拒绝。
- **跨卡已花费(#123)**:工具条显示当前累计花费,估不出价的卡如实计数
  而不是当零。
- **性能(#115、#118)**:同一份素材字节跨卡片、跨界面只读一次
  (共享引用计数 blob 缓存),200 卡场景每卡砍掉一次 IPC 与一次 blob 创建。
- **人像库选择器层级(#117)**:改为 portal 到 body,不再因父级
  `transform` 被裁切。

## Codex 通道

- **模型被改路时说清换成了谁(#131)**:上游 `model/rerouted` 通知的字段名
  是 `fromModel`/`toModel`,而此前读的是 `from`/`to`,两个读取都落到占位符,
  用户只看到「Routed from requested model to fallback model」——通知照弹却
  不说换了哪个模型,且占位符把这个失配掩盖成「看起来正常」。现在两种形状
  都吃下。
- **审批卡不再挂死(#131)**:上游在回合开始/完成/被打断时会清掉未回答的
  审批请求并发 `serverRequest/resolved` 通知,此前我们完全没接——那张卡会
  一直留着(界面只在切换会话时才清),点了也只是再发一个会被拒的响应。
  现在收到通知即撤卡,且不再对已被丢弃的请求回响应。
