# v4.9.19 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.18

## 概述

两件事:一是**长对话里看图越多、请求越大**的问题——经 Miau / 兼容桥的会话(千问、DeepSeek、Grok、Claude)现在会把较早的工具结果图从发出去的请求里换成文字占位;二是 **DeepSeek 只走 Miau**,并加入火山方舟的 V4.1 Flash 两个档位。

## 修复:长对话里工具产出的图把请求撑爆

- **现象**:让 Agent 用 `view_image` 反复看图(每张约 6 MB 的 base64),这些图每一轮都会整段重发。Codex 估算上下文时,每张图按固定的约 1844 token 算,和真实大小无关,所以请求已经几十 MB、估算却几乎不涨,基于 token 的自动压缩一直不触发,最后被网关拒掉(413 / Bad Request)。
- **现在**:发给模型的请求里,只保留最近 **4~6 张**工具产出的图(每攒够 3 张才往后淘汰一块,尽量保住提示词缓存);更早的图换成一行文字占位,**占位里带着图的来源**(本地路径或链接),模型需要再看时会按这个来源重新打开。最新的一张永远保留。
- **只动发出去的请求**:Codex 保存的对话历史不改;你自己贴的图、远程链接图、文字结果都不动。淘汰逻辑一旦出错,只打一条警告、请求原样发出,不会让这一轮失败。
- **影响哪些模型**:经兼容桥的通道——千问、DeepSeek、Grok(xAI)、Claude。OpenAI 直连不经过这一层,不受影响。
- **实测**:拿一份真实会话的记录(10 张图,请求体 56.3 MB)过一遍,图变成 4 张、请求体 22.7 MB(少 60%),占位里是真实的上传路径。真模型(Miau 生产网关上的 `qwen3.8-max`、`deepseek-flash`)问到被省略的那张图时,都会按占位里的路径重新调用 `view_image`;问到保留的那张时直接作答。
- **代价**:模型不再能直接"回头看"很早以前的图,要用就得重新取一次;每次淘汰边界往后移时,提示词缓存会失效一次。

## 变更:DeepSeek 只走 Miau,加火山方舟 V4.1 Flash

- **撤下** `DeepSeek V4 Flash 0731（Miau）`、`DeepSeek V4 Pro 0813（Miau）`、`DeepSeek V4 Flash`（Right.Codes 直连、自填 Key),并删除 Right.Codes 的 DeepSeek 通道。
- **加入**火山方舟的 `deepseek-v4-1-flash-261017`（标准版）与 `deepseek-v4-1-flash-economy-261017`（经济版)。两者与 `deepseek-flash`（Miau)走同一条通道、同一个 Miau 令牌,思考档位 low / high / max(默认 high),窗口 1M。
- **旧选择自动迁移**:已保存的 0731 → `deepseek-flash`,0813 → `deepseek-v4-pro`,`deepseek-v4-flash` → `deepseek-flash`(仅对内置网关生效,自定义网关不动)。
- **⚠️ 行为变化**:原来用 Right.Codes 直连 `deepseek-v4-flash`(自填 Key)的用户会被换到 `deepseek-flash`,**计费改走 Miau 平台余额**。

## 还没覆盖的地方

- **Claude 通道基本得不到这次淘汰的好处**:Claude 的消息转换层本来就会丢掉工具结果里的图,所以保留下来的图在上游也只剩文字。Claude 通道下 `view_image` 的结果模型能不能真的看到图,这次没有去查。
- **没有做「被网关拒绝后整体剥图再重试」的第二道保险**,Codex 官方也没有。
- 真模型验证每种情况只跑了一次,图是纯色小图,没有量化提示词缓存失效的实际花费,也没有测 Anthropic 桥。
- DeepSeek 一侧:工具往返里三个模型都没吐 `reasoning` 项,reasoning 回放这条形状没被覆盖;1M 窗口出自网关目录声明,没有用超长请求实测;渲染层 localStorage 里残留的旧 slug 不在本版处理,选择器会把它当未知模型显示,重新选一次即可。
