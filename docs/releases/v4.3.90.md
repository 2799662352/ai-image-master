# v4.3.90 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Releases 兜底
> 上一个热更新版本:v4.3.83(4.3.84–4.3.87 未发布过热更新,本次一并带给用户)

## 概览

本次是**累积发布**:自 v4.3.83 以来的 Canvas 代理增强(4.3.84–4.3.86)、Codex 0.143 升级与 4K 批量生成 OOM 修复(4.3.87),加上本版新增的 **Codex 官方对齐批次**(userMessage 对账、Plan 协作模式、统一 @ 提及插件、附件引用修复)与全量预存基线清理。

## 变更(v4.3.90 本版)

### Codex 官方对齐轨道(详见 `docs/session-summaries/2026-07-09-codex-alignment-track.md`)

- **附件引用修复**:聊天引用上传附件不再误报 `Reference path is outside allowed roots`(send 闸白名单补齐 uploads 缓存目录,与 fs 闸口径对齐);失效引用(跨机器/已清理)自动跳过并提示,不再绑架整条消息。
- **统一 @ 提及插件(MentionsV2 对齐)**:`@` 弹层现在统一搜索文件 + 已安装插件 + skills;Connectors 面板装的插件可直接在聊天里 `@插件名` 调用(官方 `mention` 输入变体,`plugin://` 通路)。
- **Plan 协作模式**:composer 新增 Plan 药丸(官方实验性 `collaborationMode`)——开启后 codex 先调研并产出计划、不直接执行;按线程记忆开关状态;推理力度取官方 Plan 预设。
- **userMessage 对账(rollout 原生恢复)**:发送消息带 `clientUserMessageId` + `text_elements`(UTF-8 字节区间);服务端回显落库为 canonical 数据;「编辑重发」的附件 chip 双源恢复——DB 优先、rollout 兜底,上传文件被清理后 chip 仍能恢复。
- **附件清理引用感知**:`AttachmentService.cleanup()` 不再盲删仍被消息引用的上传文件;引用扫描失败时跳过本轮清理(fail safe)。

### 质量与稳定

- 预存基线清理:16 个测试失败 + 3 个 TypeScript 错误全部修复(React 19 类型适配、事件联合类型窄化、jsdom 媒体 mock 等);新增 13 个测试文件覆盖上述对齐功能。

## 变更(4.3.84–4.3.87 随包带出)

- **v4.3.87**:4K 批量生成 base64 OOM 崩溃修复(blob URL 物化 + 历史丢失修复);Codex CLI 升级 0.143.0;Right.Codes 预设修复 + key 热重载。
- **v4.3.84–4.3.86**:Canvas 代理对齐官方 tldraw Agent Kit——虚拟视口(`canvas_focus_region`)、`canvas_create_shape`(几何/便签/文本/连线带绑定)、相对放置(官方 Place 动作)、z-order 编排、byAgent diff 归因。

## 兼容性与降级

- Codex 对齐全部为 additive:`clientUserMessageId` / `collaborationMode` / `text_elements` 均为不传即旧行为;旧线程/旧消息不受影响。
- Plan 模式为实验性 API,依赖 bundled codex binary(0.143)已冒烟验证;不开启则零影响。
- 附件白名单只放宽了自家 uploads 缓存目录;「任意本地文件 → 模型视觉输入」的安全边界不变。

## 升级方式

- 桌面端通过 COS 热更新自动检测下载 v4.3.90(差分更新,只下载变化部分)。
- 手动:重新下载安装包 `catimation-cyberpunk-master-4.3.90-setup.exe`。
