# v4.4.18 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.17

这一版的主线是**视频工作台**:从「能出片」补到「能编排、能对照、能交给模型」,
外加一条藏得很深的本地数据库故障 —— 它会把你正在发的消息整条打翻。

## 本地数据库不再拖垮聊天

线上报错长这样,看着像提示词写坏了,其实不是:

```
Error invoking remote method 'agent:send-message':
PrismaClientKnownRequestError ... Server has closed the connection.
```

消息压根没送到模型,除了重启应用没别的办法。**根因不是事件循环饿死,是连接数被拒。**
本地库(PGlite)的 socket server 运行时**默认只接 1 条连接**,超出时不排队,而是往
socket 写一句非 Postgres 协议的裸文本后直接关闭;而 Prisma 走的连接池默认开到 10。
于是只要两条查询在时间上重叠 —— 工作台一批卡同时回流时会同时产生历史写、附件元数据
写、线程更新 —— 池子就开第二条连接并被掐断。这解释了为什么「工作台任务多就容易犯」
以及「重启就好」(池子重建、流量退回串行)。

四层修复:

- **对齐上限**:服务端 10 / 池 1。吞吐没有损失 —— PGlite 本来就是单连接、查询在它
  那侧串行执行,多开连接换不来并行,只会把并发压到会被掐断的路径上。
- **池等待设界**:pg 的池队列默认无超时,库一旦卡住(而非崩溃),调用方会从「快速
  报错」退化成「永远不 resolve」,`try/catch` 抓不住。现在 30 秒转成普通错误。
- **worker 死了自动拉起**:此前 worker 崩掉没人知道也没人管,本会话所有数据库调用
  全废到重启为止。现在自动重生并告知「已自动恢复」;反复起不来则熔断并如实提示需要
  重启,而不是无限重试。
- **消息不再被扣下**:落库失败时消息照旧发给模型,只提示这条没进历史(重启后不会
  出现在会话记录里,也无法基于它编辑重发)。写**刻意不重试** —— 连接断在响应途中时
  写是否已提交不确定,重试会造出重复的聊天消息;读会自动重试一次。

## 视频工作台

- **重新生成不再抹掉上一版**:同一张卡保留历次成功产物,卡内可左右切换回看
  (`v1 / v3`)。此前重生等于覆盖,想对照只能靠记忆。切换只是预览,卡片的当前结果
  永远是最新那一版。
- **任意位置插卡**:卡片之间的缝隙有「＋」,不必再「加到末尾再拖上来」。
  顺手修掉一个潜伏的丢卡:超过上限时淘汰只从数据库删、内存没同步,卡片会在**下次
  启动时**才消失 —— 属于延迟发作的数据丢失。
- **多选与批量**:点卡片头部那一行选中,支持 Ctrl 加选、Shift 选区间。有选中时
  ⚡ 与删除只作用于选中项,按钮文案随之变化(「生成选中 3 张」),避免误触整页生成
  而烧掉一批额度。
- **拖进聊天栏把视频递给模型**:选中若干张直接拖到输入框,产出引用 chip。
  复用的是文件树那套既有通路,没有另造协议。
- **模型能看到你选了哪几张**:每次工作台工具调用都带上当前选中项,所以「生成选中的」
  「这几张重做」这类指代能落到具体卡片上。它是**信息**而非指令 —— 模型动手的目标
  永远由参数显式给出。

## 生成不再堵住对话

- **启动一批不再占死这一轮**:`video_workbench_start` 立刻返回,渲染在后台跑。
  此前工具调用挂在那里,模型不推理、你插话也进不来 —— 就是「启动后卡住、没法说话」
  的根因。
- **跑完主动推给模型**,取代让它轮询状态(每次等待都变成一次工具调用,又会把对话
  占死)。这份登记**跨重启存活**:渲染要几分钟,中途重启应用后照样会推 ——
  那是一句承诺,不能被进程重启吞掉。
- **重启接管真正生效**(4.4.17 的「已知未做」之一):此前水合时抢先把在飞卡片判死,
  导致对账永远拿到空集合、接管形同不存在。现在原样读回、交给对账问上游。

## Agent 与市场

- **工作台与 `generate_video` 的 skill 同等待遇**:`catimation-video` 认领了
  「视频工作台 / 批量出片 / 多镜」这些触发词,`add_tasks` / `start` 会点名让模型
  先加载 skill。此前从工作台出片不会触发它,提示词质量因此掉档。
- 素材口径(参考视频/音频 ≤3 且合计 ≤15s)在建卡三个工具里都写死了;新卡默认联网、
  配音默认开。
- 市场已更新:`catimation-video@1.0.25`。

## 验证

- 全量单测与 typecheck 债务闸随 CI 执行;本轮新增用例均先写失败测试再实现,
  关键回归测试逐条验过红绿(移除修复后必须变红)。
- 数据库那条根因用**真 PGlite + 真连接池**端到端验过:先在默认上限下复现出连接被
  掐断,再证明新配置下 12 条并发一条都不失败(`npm run verify:pglite-cap`)。
- worker 监管用假 worker 驱动真实接线跑完整条链:意外退出 → 重生 → 熔断 → 通知。

## 已知未做

- **库「卡死」而非「退出」时不会自动恢复**:只能靠 30 秒池超时兜住(报错、降级、
  对话可继续)。刻意不做「静默即判死」—— PGlite 执行查询时会阻塞自己的事件循环,
  一次合法的长事务同样不回应探测,按静默去杀等于毁掉正在跑的真实事务。
- **崩溃瞬间在飞的写不会重试**,只有读会。理由同上:重试可能已提交的写会造出重复
  记录,代价比多一次报错大。
- 接外部 postgres(5432)时不适用上面这套自愈,那条路径属于开发环境。
- 图片生成仍无任务恢复:请求中途断连后,即便服务端已出图也找不回来(上游无异步
  任务 ID,非本端未做)。
- 工作台未出片的卡拖进聊天栏会静默落空 —— 没有产物就没有东西可递;选中态仍会同步,
  模型下次调工具照样看得见这几张卡。
- 开发版与安装版同时运行会撞端口(`os error 10048`)。
