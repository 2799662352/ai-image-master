# v4.7.1 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.7.0

## 概览

补丁版,只有一件事:修掉画布上传图片必崩。

## 往画布里放图片会整块崩掉

在 Codex 画布上拖一张图进去,整个画布被卸载,弹出「Something went wrong / Reset
data」的错误页:

```
ValidationError: At asset(type = image).props.src: Expected a valid url,
got "local-file:///C%3A/Users/…/image_….png"
```

四条放图/放视频的路径全部受影响:从系统里拖拽、agent 调 `insert_image_into_holder`
放进占位框、`create_image_version` 生成新版本、从左侧文件树拖进画布。

### 为什么会这样

画布刻意不把图片的字节存进 tldraw 自己的库里 —— 那正是之前反复吃满内存、导致应用
自动重启的根因。它存的是**路径**:图片走 `local-file://`,视频走支持拖动进度条的
流式地址,剪贴板里没有磁盘文件时退回到浏览器内存引用。

但 tldraw 自带的地址校验只认 `http`、`https`、`data` 和它自己的内部协议。上面这三种
一个都不在名单里,于是每一次插入都在写入库的那一步被拒,并把整棵画布卸载。

### 改法

用 tldraw 自己提供的扩展点,给画布单独声明一份资产校验规则,把我们这两种地址加进
白名单。**仍然是白名单** —— `file:`、`javascript:` 这类照旧被拒,不在名单里的地址
一律交回 tldraw 原本的校验,所以将来 tldraw 收紧协议我们会自动跟上。

已经存在画布里的内容不受影响,不需要清数据:校验发生在写入那一刻,坏记录从来没能
存进去过。

### 顺带补上的测试缺口

画布的冒烟测试此前建的是一个**线上永远不会运行的**存储实例(没有注入资产校验规则),
所以这个崩溃在测试里看不见。现在测试和生产用同一份配置,并且专门留了一条用例:如果
有人把这份规则去掉,测试会立刻红。
