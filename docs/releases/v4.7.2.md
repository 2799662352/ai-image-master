# v4.7.2 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.7.1

## 概览

补丁版,围绕上个版本刚落地的**图层分离**:它拆不动你自己的历史图,你打的提示词也没
发出去。顺带把它从「参数区的一个勾」返工成「工具栏的一个动作」,不再牵连普通出图。
另有一条 Windows 打包侧的修复。

## 拆不动自家的历史图

对一张历史图点图层分离,回来的是:

```
The parameter `image` specified in the request are not valid:
The request failed because the image format is not supported by the API.
```

参数名对、模型对、开关对,只有格式不对 —— 而且不说该转成什么。

原因是上游 Seedream 5.0 Pro 的 `image` 只吃 PNG / JPEG,而**本应用存到 COS 的历史图
是 `.webp`**。也就是说「拿历史图去拆」是必然踩中的主路径,不是边缘情况。

### 改法

在发请求前统一转码。放在 `ApiService.generateImage` 这个收口处,因为工具栏、批量队列
的 worker、MCP agent 三条路都要经过它 —— 在各调用方各修一遍迟早漏掉一条。

- 已经是 PNG / JPEG 的**链接原样放行**:保持链接形态让上游自己去取,不必把几 MB 的
  base64 塞进请求体
- 没有后缀的先看真实类型,是 PNG 就直接放行,省掉一次无谓的重编码
- 只有 WebP / 未知格式才取回来转成 PNG

**转 PNG 而不是体积小 5–10 倍的 JPEG**:WebP 可能带透明通道,转 JPEG 会把透明区压成
黑块,而这张图正是拆分的依据 —— 底图错了,整组图层跟着错。

顺带拦住了小于 512px 的图(上游对此同样只回一句语焉不详的参数错误),现在会直接告诉
你「300×900,要求最小边不低于 512px」。

## 提示词没有发出去

上游支持用提示词指定**要拆出什么**(「只把人抠出来」「把文字单独拆一层」),留空才是
「自动全拆」。但两条路径上这个字段都被写死成了空串 —— 你打的字根本没进请求。

现在出图页取出图框里那句,批量页按当前模式取抽卡提示词或多提示文本。留空仍然合法,
含义就是自动全拆。

## 图层分离:从「参数区的勾」改成「工具栏的动作」

上个版本它是参数区的一个复选框。勾上之后「生成」按钮的含义就变了 —— 点生成不再是
出图而是拆图,还得连带把比例和数量灰掉、切模型时自动关掉、分辨率换一套档位再换回来。
那些全是为了让拆分假装成一次出图而付的代价。

现在它是视觉工具栏上跟 多角度 / 打光 / 全景 / 导演台 同级的一个按钮:

- **常驻,不随模型出现或消失** —— 渠道由这个动作自己钉住 Seedream 5.0 Pro,你不该
  为了看见这个按钮先去切模型
- **拆哪张说得清** —— 用那一排本来就有的选图器选中的那张
- 按下 = 选中待拆的图,下方主按钮改名「拆图」,点它才真的跑(拆分按张计费,一张复杂
  图能出 1 张底图 + 最多 16 层,不做成点一下就扣钱)
- 比例 / 数量 / 分辨率**完全不受影响**,普通出图一个字都没变

**状态点完不掉**:同一张图常常要换几种说法试(「只要人」「只要背景」「把文字也拆
出来」),每次都得重新选图就没法比。退出由那个按钮显式负责,再按一次即可。

**批量页的主按钮在这个状态下恒可点**:平时批次一跑,主按钮就退化成不可点的「正在
生成」(只剩取消),把拆分挂在它后面等于跑一次堵一次;而拆分只是往队列里塞一张、由
空闲 worker 捡走,没有理由要等。

## Windows 上装不上指定版本的 Codex

`ensure-codex` 在 Windows 下用 `spawnSync` 调 `pnpm.cmd` 会直接 `EINVAL` —— Node 的
安全加固要求 `.cmd` / `.bat` 必须走 shell。也就是说需要下载新版 Codex 时,那条下载
路径根本起不来,只会留下一句语焉不详的报错。这条与上个版本刚加的「版本核对」配套:
核对发现版本不对,得能真的把新版拉下来。
