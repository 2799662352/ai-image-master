# v4.4.14 发布说明

> 发布渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 兜底
> 基线版本:v4.4.13

## 概览

本版一条主线:**子代理(多智能体)从不可见变成可见、可归属、可计费**。

起因是一次核查:捆绑的 Codex 0.145 里,多智能体能力**默认就是开着的**——模型的系统提示词里本来就写着它是一个代理团队的主控,并给了它孵化、等待、中断子代理的工具。而我们的界面此前完全不认识这套东西:子代理干的活看不见、它调用工具产生的图会落到错误的会话、它烧的 token 不计入任何地方。本版把这三件事补齐,并在实测通过的通道上启用了更新的 V2 代际。

## 子代理

- **工具调用不再落错会话(正确性修复)**:子代理调用生成图片、或向用户提问时,此前会归属失败并退回"当前打开的那个会话"——图会出现在你碰巧正在看的对话里,提问卡片会弹给一个毫不相干的会话。现在按孵化关系正确归属。
- **委派卡片**:父对话里能看到一张卡,显示交出去的任务、使用的模型、以及每个子代理的状态与它的回复。子代理可以跑与主对话不同的模型,所以模型名单独列出。
- **子代理花费**:每个子代理消耗的 token 显示在它自己那一行。刻意不并入主对话的用量统计——那个数字驱动上下文窗口指示器,混入子代理的数据会让你以为主对话的上下文快满了。
- **多智能体 V2**:在实测验证过的两条 GPT 通道上启用。V2 的代理有名字(如 `/root/pong_agent`)而不是一串 UUID。Claude 与 Grok 通道保持上一代,因为 V2 会加密交给子代理的任务,而非 OpenAI 后端能否解开尚未验证。
- **稳定性**:子代理的事件此前会无声地堆积在一个永不清空的缓冲区里,填满之后会开始丢弃主对话真正需要的数据(表现为回复偶尔丢开头几个字)。现在不再堆积。

## 已知未做

- 取消主对话的回合时,正在运行的子代理不会被一并停止,它们会跑完自己的任务。
- 应用重启时若有子代理在运行,重启后无法与它们重新建立联系。
- 界面上没有"让子代理做这件事"的入口,也没有任何东西提示模型何时该委派——所以除非你在对话里明确要求,子代理不会自己出现。
