# v4.7.4 发布说明

> 更新渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 存档
> 上线版本：v4.7.3

## 概述

这一版只修一件事：**用真人照片当参考图发视频，第一次就能发出去。**

## 真人参考图不再被上游拦下

用真人照片当参考图，提交视频会被上游拒掉：

```text
InputImageSensitiveContentDetected.PrivacyInformation
```

上游只对**直传的图片链接**做真人检测；素材库里的图（`asset://` 引用）不查。人像库本来就会把参考图登记成素材，所以理论上早该绕开——但没有，因为两个原因叠在了一起。

### 登记发生在提交之后

登记的确在做，只是排在了请求发出去**之后**。等它跑完，这次提交里带的还是原始图片链接，该被拒还是被拒。

用户能摸索出的绕法是：先去人像库手动传一遍，再回来用 `@` 引用——第二次就成了。vvdance 那条路上大家习惯了先传后用，所以这个缺陷一直没显出来；平台这条路缺的正是这个前置动作。

现在登记挪到了提交之前：登记完拿到素材引用，替换掉图片链接再提交。**第一次就能过。**

### 「默认上传人像库」开关会把登记整个关掉

这个开关原本只影响一件小事——要不要顺手把参考图存进库里，方便下次跨镜复用。关掉它没什么损失。

但登记现在是过审的前提，于是这个开关意外地变成了「真人图能不能发出去」的总闸。而它字面上讲的是「要不要进库」，两件事在使用时毫无关联，出了问题也不会有人把它们联系起来。

现在开关回到它字面本来的意思：**登记照做，开关只决定登记完之后要不要在人像库里看得见。** 关着时素材会被自动隐藏（软删，随时可在库里恢复），不占配额，也不影响这次提交。

## 已知限制

万相 3.0 / 3.0 Prime 不参与这项改动——它们的上游不接受素材库引用，参考图仍按图片链接直传。

## 其它

- 手动上传人像库的三个入口（工作台选图弹窗、人像库页、平台库）已复核，均按当前计费模式正确分流，本版未改动。
