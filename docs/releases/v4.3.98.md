# v4.3.98 发布说明

> 发布渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 兜底
> 基线版本：v4.3.97

## 概览

本版修复「离开一段时间后再点 `ask_user` 选项卡就卡住」的假死问题。这不是
上游 Codex 缺陷，而是我方选项卡生命周期缺口，已用两层修复彻底解决。应用
功能与 app-server 协议保持兼容，无需迁移现有会话或配置。

## ask_user 选项卡假死修复

- 根因：`ask_user` 调用链上同时挂着两个约 33 分钟的超时（渲染层工具等待
  窗口与 Codex 侧 `tool_timeout_sec`）。用户离开超过该窗口后回合已被超时
  终结，但卡片没人清理，仍留着可点按钮；迟到的点击在主进程因 pending 已
  删除而被静默丢弃，表现为点了没反应。
- `ToolRouter`：`ask_user` 单独给 6 小时等待窗口，其他工具维持约 33 分钟
  不变——等人和等算力是两回事。
- Codex 启动配置：catimation 工具超时天花板从 2000s 抬到 25000s（约
  6.9 小时），严格高于 6 小时窗口，保证迟到的点击先于 Codex 自身超时到达；
  其他工具仍由 ToolRouter 在 33 分钟内显式返回，不受影响。
- 渲染层：回合终结（完成 / 取消 / 终态错误）时冻结该线程所有 pending 选
  项卡并标记过期，同时 resolve 挂起的 promise 防泄漏；瞬态可重试错误不
  冻结。
- 过期卡片显示明确提示（「该提问已过期——直接在下方输入框回复即可继续」），
  不再留死按钮。
- 修复后行为：6 小时内回来点击可直接继续跑；超过 6 小时或回合已死，卡片
  明确变为过期态并告知如何继续。
- 详细分析见 `docs/2026-07-15-ask-user-card-timeout-fix.md`。
