# v4.9.27 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.26

## 概述

两件事:Codex 引擎升到 0.166.0;视频工作台的卡片拖进聊天栏时,不论什么状态都会带上一份「卡片清单」。

## 变化

- **Codex 升级到 0.166.0**。对照官方发布说明逐项核对过,我们的代码不需要跟着改:新增的 `codex-exec-server` 可执行文件我们不打包(已在打包清单里写明理由);线程卸载延迟缩短、全新档案默认开记忆 v2 这两项,我们已钉的启动参数照常生效;模型目录里 GPT-6.1 Terra 的默认窗口按官方 500K 补进了上下文表。
- **卡片拖进聊天栏,每张卡都会附一份清单 `workbench-card-xxxx.md`**。草稿、渲染中、失败、已完成都有;有产物时是「清单 + 视频文件(或云端地址)」,没产物时只有清单。清单里写:状态(如「成功(当前 v2)」)、规格、请求种子与**实际种子**、任务号、创建 / 完成时间、当前提示词全文、产物地址(本地 / 云端 / 上游临时)、历史版本(每版的时间、地址和提示词首行,最多 20 版)、参考素材展示名。历史版本只放首行是为了不让清单过长;要看某一版的完整提示词,让 agent 用工作台的导出工具按卡片 id 读。
- **一次拖多张卡,只生成一份合并清单** `workbench-cards-N.md`(每张卡一段),只占一个附件位置,不会因为每张卡各带一份清单把 20 个附件的上限挤爆。附件位置不够时,先丢的是视频附件(有云端地址就改成写进输入框的链接),不是清单。
- **本地视频已被清理时不再整张卡放弃**:以前卡片上还记着本地路径、文件已被 7 天清理扫掉时,拖拽直接跳过,连清单也没有;现在清单照常生成,产物退到云端地址,有云端地址就不再误报「已跳过」。
- 状态文案修正:已完成且有地址的卡写「成功」,只有三级地址全部失效时才写「成功过,但产物地址已全部失效」。
- 参考素材仍然只列展示名,不含路径、URL 和素材字节。

## 注意

- **清单里的本地路径只在这台电脑上有效**,换电脑后只有云端地址能用。
- 清单随提示词只给模型一个文件路径,不内联全文;模型要自己打开才读得到。
- 清单里的「本地文件」只是卡片上记的路径,标注了「可能已被 7 天清理」,不代表文件一定还在。

## 已验证

- Codex 0.166.0:所有 CI 检查通过,冒烟脚本(恢复线程、记忆)通过。
- 卡片清单:说明书、拖放、拖拽载荷三组测试共 86 条;变异检查 33 种(其中一种是重复判断的等价变异,已删掉重复代码)全部被抓到;视频工作台 / 聊天栏 / 文件栏相关目录整体通过,`typecheck:ci` 无新增。

## 还没覆盖的地方

- **没有在真实安装包里拖一次卡片看聊天栏的附件条**,只有组件级测试。升级后请拖一张完成卡看看清单是否出现,再拖多张看是否只有一份合并清单。
- **模型会不会主动打开清单没在真实会话里验证**。
- Codex 0.166.0:没在全新档案上实测记忆 v2 的实际成本和效果;GPT-6.1 Terra 的 500K 只来自打包的模型目录,没对真实账号验证。
- 清单里不带每一版当时用的参考素材名;要看某一版的素材,仍然要让 agent 读那张卡。
