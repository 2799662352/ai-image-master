# v4.5.3 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.5.2

## 概述

4.5.2 把「改几个词」从「重发整板」压成了单卡调用。这一版是那条路的收尾:让 AI
读看板也变成分层的,而不是一次把整块看板搬进脑子。

用户侧的表现:让 AI 改一张卡、挪几张卡,页面上更快出现动静,中间那段「右边一直
转」的静默更短。

配套 skill 已随插件市场发出,本次桌面端更新带的是工具本身。

## AI 读看板改成分层的

以前 AI 想知道「第 3 张是哪一镜」,只有两条路:看被截到 120 字的开头,或者把整板
两万字符全拉下来。而经 sd2-pe 工程化的提示词开头结构是固定的(景别、机位、光线
那套开场),同一页里**每张卡的开头看起来都差不多** —— 截断在这里恰恰因为模板化
而最没有信息量。

现在有四级:整体概览 → 页摘要 → **卡片摘要** → 全文。

**卡片摘要**是 AI 写的一行电报体(「主角跳车 · 夜外 · 追兵逼近」,≤40 字)。它绑在
写它时的那份提示词上 —— 提示词一改,摘要立刻被判过期、**不再展示**,只留一个信号
告诉 AI 可以重写。所以你永远不会看到一条「看起来很权威、其实早就作废」的旧摘要。

写摘要不影响生成、不进提交参数,也不会作废 AI 手里正在用的看板快照。

## 导出默认只出骨架

`export` 现在默认只回 id 和顺序,要全文得显式要。

因为 4.5.2 把 `apply` 收窄成纯结构工具之后,「带全文的整板导出」只剩「整板重建」
一个用途,却仍是最容易撞上静默截断的调用 —— 而那在这里不是慢,是**数据丢失**:
`apply` 是声明式的,回写一份被截断的内容会把截掉的字段清成默认值。

重排、只改其中几张这类活本来就不需要看别人的提示词。

## 整页重排一次做完

新增整页重排:一次给出该页完整顺序。重排是顺序相关的、不能并发,所以以前挪 10 张
卡就是 10 次串行往返。要求给完整的 id 列表 —— 只给要挪的那几张会被拒绝,因为
「没列出的怎么排」是歧义,而 IR 那条老路上它会静默把没列出的卡挤到后面。

## 少发的 token

改提示词和挪单卡这两个调用不再回带全局概览 —— 它们在定义上不可能改变它,而这两个
工具恰恰是设计来一回合并行调好几次的,回带就是把同一份内容复制好几遍。

跨工具的选择关系(什么活用什么工具、哪些能并发)从各个工具描述里搬到了 MCP 的
server instructions,不再每个工具重复一遍。

## 工具调用埋点

每次工具调用的耗时、成败、错误类型现在会记进 `<用户数据>/logs/tool-calls-<日期>.log`,
一行一条 JSON,字段名照 OpenTelemetry 的 GenAI 语义约定。

这是为了让「这些优化到底快了多少」有数字,而不是停在推理。

**不记参数和返回值** —— 那里面就是用户写的提示词。错误原因也做了截断:有的工具会
把提示词全文放进错误里帮 AI 自纠,不截就等于把用户内容写进日志。

## 顺带

- `apply` 拒绝一次写入时,该换用哪个工具的提示从 JSON 里抬到了最前面。
- 修正工具注解:重复调用的语义按 MCP 规范核对过,破坏性标记显式声明而非依赖默认值。
