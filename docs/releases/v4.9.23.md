# v4.9.23 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.22

## 概述

一件事:**Codex 页 DeepSeek(Miau)通道的模型次序调整,以及后台「记忆 / 会话自动起标题」改用火山标准版模型。**

## 变化

- **模型选择器次序**:DeepSeek 组现在按 `火山 V4.1 Flash` → `火山 V4.1 Flash 经济版` → `DeepSeek V4 Pro` → `DeepSeek Flash` 排列(火山在前,官方在后,`V4 Pro` 排在 `Flash` 前面)。只是次序变了,模型本身和各自的参数没动;已有的选择不受影响,通道默认对话模型仍是 `deepseek-flash`。
- **记忆与会话自动起标题改用火山标准版**:这个通道的四个模型(火山两个 + 官方两个)的后台记忆提取 / 合并和自动起标题,统一走 `deepseek-v4-1-flash-261017`(原来是 `deepseek-flash`)。统一成一个值,是因为记忆模型在启动 Codex 时就固定了、同一通道内切换模型不会重启,按模型分路会在切换后用错模型。

## 注意

- **官方两个模型(`DeepSeek V4 Pro` / `DeepSeek Flash`)的后台记忆和起标题也会按火山标准版计费**。同一时段它的单价是 `deepseek-flash` 的 6.7 倍,单次记忆请求约 ¥0.0005(原约 ¥0.00007),绝对值很小,但会出现在用量明细里。

## 还没覆盖的地方

- **火山标准版的记忆请求没有对生产网关验证过。** 记忆请求失败不影响对话,最坏是白花一笔、记忆没更新;上线后需要看一眼日志里的 `[thread-title] model=…` 行和记忆产物确认能用。
- 没有在真实窗口里看过选择器的实际次序(自动化测试已覆盖次序)。
