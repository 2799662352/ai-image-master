# v4.9.18 发布说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.9.17

## 概述

新增「深度捕捉」:把一段已有视频转成灰度深度视频(近亮远暗),可以当运动参考喂给下一次生成。它是 `generate_video` 的一个变体(`model: "depth"`),不是新工具,Agent 在聊天里直接可用。同时修了发布脚本里 COS 报错显示成 `[object Object]` 的问题。

## 新增:深度捕捉

- **怎么用**:在聊天里给 Agent 一段视频(路径、链接,或刚生成的片子),说「提取深度 / 深度视频 / 深度捕捉」。走平台余额或 Miau 密钥,经 Miau 网关出片;本地文件会自动中转到云端再提交。
- **产物**:和源视频同分辨率、同帧数、同时长的灰度深度视频,会像别的视频一样进聊天、落历史页,并转存到云端(腾讯的临时存储只保留 7 天)。
- **分辨率不用选**:`480p` / `720p` / `1080p` 三档产物和价格完全一样(后端是腾讯云点播的视频深度估计,没有分辨率参数)。
- **计费**:按次,不按秒。网关默认 ¥0.5 / 次,5 秒的测试片实测扣 ¥0.5;腾讯自己的单价没有公开。
- **它很慢,耗时随源视频时长明显增长**(用 Miau 网关实测,三条长片同时提交):

  | 源视频 | 结果 | 总耗时 |
  | --- | --- | --- |
  | 5 秒 / 0.8 MB | 成功 | 约 1.5 分钟 |
  | 60 秒 / 720p / 20 MB | 成功 | 约 22 分钟 |
  | 60 秒 / 1080p / 86 MB | 成功 | 约 22 分钟 |
  | 180 秒 / 60 MB | 34 分钟后仍未出结果(没等到头) | — |

  所以建议**先把源视频截到真正要用的长度(一般 ≤60 秒)**再做。应用对深度任务最多等 **50 分钟**(其它模型仍是 30 分钟);超时会报「轮询超时」,但腾讯那边可能还在处理、照常计费。
- **限制**:源视频必须是公网可下载的视频,`asset://` 素材库地址不收;本地文件超过 100 MB 会在提交前被拦下并提示怎么压(这是应用自己设的保守上限,腾讯没有公布上限)。失败时腾讯只回笼统的 `depth job failed`,先查源视频链接是否真能公开下载。
- 深度捕捉不出现在视频工作台里。

## 其他

- 发布脚本:COS 报错不再显示成 `[object Object]`,预检失败时能看到真正的原因。
- 插件商城 `catimation-video` 随本版发布后升到 **1.0.46**(带「深度捕捉」用法)。已经装过这个插件的用户需要重新安装一次才会拿到新版(没有查到自动升级)。

## 还没覆盖的地方

- **180 秒的片子没有测到出结果**,不知道它最终要多久、会不会成功。
- **完整链路没有在 Electron 里跑过**:用真实令牌验证时,提交、轮询、结果解析、下载用的是应用里同一份代码,但在普通 Node 环境里跑;本地文件中转到 COS 那一段是照应用的做法复刻的。Electron 的网络层、IPC、落盘转存这几段只有单元测试。
- 腾讯的真实单价没对上(价格页没有这一项,需要在点播控制台看日结账单)。
