# v4.4.3 发布说明

> 发布渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 兜底
> 基线版本：v4.4.2

## 概览

本版聚焦「同一对话内自由换模型」：修复了活跃会话在 Grok 与 GPT 之间
切换模型时静默失败的根因，落地按线程的 Provider 路由持久化，并同步
升级 Codex CLI 至 0.144.6 热修版本。

## 活跃线程跨 Provider 切换（核心修复）

- 根因：Codex `thread/resume` 对**仍在加载中、有订阅者的线程**会静默
  忽略 `modelProvider` 覆盖（上游 `thread_processor` 行为，源码级确认），
  导致 UI/数据库认为已切换、实际线程仍绑在旧 Provider，下一回合打到
  错误端点报错。
- 修复：活跃线程改走 `thread/fork` ——历史完整复制、覆盖参数生效，
  会话映射重指向 fork 出的新线程，旧线程 `thread/unsubscribe` 释放；
  冷线程（应用重启后）沿用 `thread/resume` + 覆盖；从未完成过回合的
  线程直接放弃映射，下次发送在新 Provider 上开全新线程。
- 一个对话使用中不再阻塞另一个对话换模型：切换以线程为粒度，
  互不影响。

## 按线程 Provider 路由持久化

- `AgentThread` 新增 `gatewayId` / `modelProvider` 字段（含热更新
  就地迁移），每个会话钉住自己的网关与通道，切换全局模型选择
  不再改写既有会话的路由。
- 渲染层按线程记忆模型绑定：切换会话时自动恢复该会话最后使用的
  模型，发送时记录本次使用的模型。

## Codex CLI 0.144.6 热修适配

- 内置 Codex CLI 0.144.5 → 0.144.6（SHA-256 钉扎校验），生产启动
  参数集全量冒烟通过。
- 采纳上游热修修正：GPT-5.6 家族（sol/terra/luna）上下文窗口
  372K → 272K，目录默认值与 Codex 原生窗口两张表同步更新，
  上下文钉扎判定与二进制原生解析保持一致，避免多余的重启与钉扎。
