## 版本跳跃:4.4.14 与 4.4.15 未单独发布

两版的发布说明都保留在 `docs/releases/` 里作为改动记录,但都没有真正推上线:

- **4.4.14** 在发布前的逐条核查中发现子代理显示失真,修完后并入 4.4.15。
- **4.4.15** 的构建停在人工审批门上未放行;其间又攒下四组出图修复,于是直接发
  4.4.16 —— 因为 4.4.16 从 main 构建,而 main 已包含 4.4.15 的全部提交,
  一次审批即可把两批改动一起送出,批两次只会拿到同样的东西。

所以**本版实际内容 = 4.4.14 + 4.4.15 + 4.4.16 三批改动**,用户从 4.4.13 直接升到
4.4.16。已核实(而非推断):

```
git merge-base --is-ancestor b416a79 v4.4.16   # b416a79 = 4.4.15 的合并提交
# 退出码 0 —— 4.4.15 的内容确在 v4.4.16 中
```

`v4.4.13..v4.4.16` 共 8 个提交,依次是:子代理事件不再堆积(#139)、归属修复与
委派卡片(#140)、状态如实显示(#142)、内置通道不许指回被屏蔽域名的守护测试
(#138)、时长补齐(#144),以及三次版本号提交。

## 出图

- **谷歌生图返回 URL 时不再报「生成失败」**:Gemini 原生端点并不总是回内联
  base64——网关把产物传到对象存储后,整条响应里只有一条写在文本里的预签名 URL。
  此前的解析只认 `inlineData`,于是图明明已经生成成功,界面却报「未能从响应中
  提取图片」。现在文本里的图片地址同样收下。
- **顺带修掉预签名 URL 被截断**:同一段解析服务的另一条分支(Chat Completions
  文本内嵌图片)会把地址截断在 `.png` 处,丢掉后面的签名参数——这样的链接必然
  403。现在连查询串一起取。

## 网络抖动下的出图

- **生成失败不再无声无息**:单图生成页此前遇到任何失败——网络断连、上游报错、
  重试耗尽、超时——都只是把按钮变回"开始生成",既不出图也不报错,原因只在
  开发者工具里看得到。现在会把上游给的原因直接告诉你。同一个原因连续失败两次
  时的第二次、以及并发点两次时把别人的图算成自己的,一并修正。
- **图片加载失败会自己重试**:生成结果网格、大图预览、历史卡片与历史大图,
  遇到网络抖动会退避重试两轮,仍失败才显示占位。此前生成页是浏览器原生裂图、
  历史卡片则一次判死不自愈。重试用重新挂载而非给地址加参数——这些是预签名
  地址,改查询串会让签名失效。
- **转存重试**:出图后把字节抓回本地、再推云端的那一步此前只试一次。它一失败
  就同时没有本地副本也没有云端副本,历史里只剩一条几小时后过期的临时地址。
  现在会重试,但对签名过期(403)这类确定性失败不做无谓重试。

## 已知未做

- 图片生成没有任务恢复:请求中途断连(或应用被关掉)后,即便服务端已经出图,
  结果也找不回来。**这一条经实测确认是上游封死的**,不是我们没做:
  - API易官方文档原话——「不提供图片生成的异步任务 ID 查询接口」「断开连接
    结果丢失但仍会计费」;探测 `GET /v1/images/generations/{id}` 回 404。
  - 同一网关的 `/v1/responses` 路由虽在,但会把 `background: true` 吞掉
    (实测回包是 `"background": false, "status": "completed"`),按 id 取回也
    因网关按模型路由而失败。
  - Miau(new-api)网关同样没有异步出图路由(404);上游 issue #4711 / #4921
    至今是未实现的功能请求。
  - 因此可行的方向是网关厂商自己也推荐的「自建异步外壳」:把请求下沉到主进程
    执行并持久化在飞记录。它能扛渲染进程重载/崩溃,扛不住应用退出。此方向已
    调研完毕但**暂缓实施**(等出图侧改造为异步后再定)。
- 视频工作台的重启接管目前是失效的:`ensureHydrated` 在水合时先把在飞卡片改写成
  `failed`,随后的 `reconcileInFlight` 按 active 过滤必然为空,`adopt()` 在真实
  重启路径上从不执行。单测因手工构造 running 卡片绕过水合而未能发现。本版未修。
- 开发版与安装版同时运行会撞端口(`os error 10048`):`pickFreePort` 探到空闲、
  绑定前被另一实例抢走。本版未修。
