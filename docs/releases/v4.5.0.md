# v4.5.0 发行说明

> 更新渠道:腾讯云 COS 热更新(`releases/latest.yml`)+ GitHub Release 存档
> 上线版本:v4.4.30

## 概述

这一版围绕同一个主题:**别让 agent 一次吞下或吐出整块看板，别让它相信自己
没有的能力，也别在片子还能救回来的时候告诉用户「没了」。**

抬到 4.5.0 而不是补丁位，是因为其中两处改了「谁是真源」这一层的模型:视频
的持久句柄从预签名地址换成了 `taskId`，工具调用在千问通道上换了协议桥。

## 视频不会再无声丢失

一次断网就能让一条已经生成好的视频彻底消失 —— 卡片显示「已完成」，播放却
加载不出，本地和 COS 都没有副本。这一版把这条链路从头补到尾。

- **`taskId` 才是持久句柄。** 上游返回的 `content.video_url` 是一条 24 小时
  就过期的预签名地址（有效期写在 URL 的 `X-Tos-Expires` 里），而开发文档
  §3.1/§3.4 的模型是任务记录一直在、随时可按 `taskId` 重查。此前我们把这条
  地址当成成品快照到卡片上，它一坏就只剩花钱重生成。现在总是先重查拿一条
  新签发的地址，旧地址只作兜底。
- **下载到手的字节不再被自己人删掉。** 归档步骤（attachment ingest）失败时，
  一个无条件的 `finally { unlink }` 会把刚花几分钟下完的 mp4 一起删除。下载
  一旦成功，那份字节就是唯一不会过期的副本，后面每一步只能做增量 —— 归档
  只决定文件放在哪，决定不了它还在不在。
- **手动「重新保存」。** 自动重试只覆盖到 21 分钟（任务之后从主进程内存表
  清掉），中间到 24 小时那段此前是空的。按钮不重新生成、不花钱。
- **落盘失败不再一次定生死。** 即时重试从 9 秒放宽到约 75 秒，失败后再按
  1/5/15 分钟后台续试，成了就原地升级回「已保存」。
- **播放失败不再是终点。** 候选地址变化或网络恢复会自动重试，失败态另给
  「重试播放」和「在浏览器中打开」。远程源从二选一改成候选列表逐个降级，
  每个候选 60 秒窗口、封顶指数退避 + full jitter，且只重试瞬时错误
  （`MediaError.code` 区分，`SRC_NOT_SUPPORTED` 零等待换源）。
- **不再含糊其辞地说「可能已过期」。** 签发时间和有效期就在 URL 的 query
  里，直接解析:没过期就明说是网络不通，过期了才提重新生成。实测那条报告
  加载失败的地址签发才 13 分钟、还有 23 小时 —— 一句含糊的措辞会把人推去
  花钱重跑一条其实还能下载的片子。

## 工作台:三条链路全部收窄

用户只想把 17 张卡改成「480p + 联网 + 智能时长」，agent 却导出整板再回写，
中途 JSON 解析失败重来，全程盯着 RUNNING。

- **`apply` 不再自称「多卡改动首选」**，开头改成三条分流，把 `set_spec`
  从第 8 条提上来。工具选择靠描述竞争，最响的那句会赢，不是最对的那句。
- **IR 支持「只占位」条目**:只给 `id` 表示「这张卡放这个位置，内容一个字
  别动」，解开「声明式 + 重排 = 必须携带全部内容」这个死结。
- **`apply` 硬闸**:一次最多 5 张内容卡，占位不计入（20 张卡重排仍是一次
  调用）。超限整份拒绝、零写入并点名该换哪个工具 —— 拦而不是劝。
- **`export` 加 `skeleton` 与 `cardIds`**，读侧补上与写侧对称的收窄；整板
  超预算改为降级回前缀 + 续取偏移，不再拒绝服务。
- **堵死「去磁盘找看板」**:看板活在运行中 app 的 IndexedDB 里，盘上没有
  镜像文件，而 `status` 里的提示词截断到 120 字却没说全文去哪拿。两处都
  写清楚了。

## 千问通道接上 namespace 桥

用 Qwen 3.8 Max 时 agent 反复宣布要做某事却不动手，一次会话刷出 59 条
`unsupported call: `（工具名为空）。codex 把 MCP 工具包进
`{"type":"namespace"}`（OpenAI 私有扩展），标准兼容后端静默丢弃后照常返回
200 —— 模型压根看不见工具。把 qwen 通道的 `compatibilityPolicy` 改成
`responses-namespace-bridge`（这座桥早就为 grok 写好了，qwen 当初关着），
并加守护测试钉住别再改回 `none`。

## 关掉流空闲看门狗

它的 10 分钟预算是照着 shell 命令和审批提示标定的，但我们自己的 MCP 工具
本来就会长时间静默:`tool_timeout_sec` 是 2000 秒，`generate_video` 轮询
Seedance 任务几分钟不发一个事件。于是看门狗在渲染中途终止健康回合，用户
看到的是「应用把我花钱跑的渲染取消了」。

代价是真卡死的 app-server 不再自愈。若该问题复现，应把阈值抬到大于工具
超时（如 40 分钟），而不是恢复 10 分钟 —— 任何低于 `tool_timeout_sec` 的
值都会继续误杀。

## 看图与音频能力纠偏

- **一次看多张图**:`file_urls` / `file_paths`，顺序即身份，任一失败整条
  报错不静默跳过。
- **PDF 走 `file` part 原生解析**（此前发 `image_url`，上游读不出内容）。
- **接上 `qwen3.8-max`**（`model="flagship"`，默认仍是 plus）。
- **千问听不见声音**:`understand_video` 是抽帧看画面，能读烧进画面的字幕，
  听不见台词、音乐、音效和语气，现在要求永远不要说「我听到……」。
  `ffmpeg-win` 里「把音频包成波形 MP4 喂给它」那条被标为废弃 —— 那样模型
  只会认真描述波形图然后开始编，一个看起来有答案、实则全是杜撰的回复，
  比报错糟得多。

## 知识库术语保留英文原词

`dolly in` / `rack focus` / `smears` / `impact_frames` 是模型训练时见到的
确切词形，技法标签更是 sakugabooru 的数据集标识符。中文对译不是等价物 ——
换过去等于把精确坐标换成大致方向，标签类的中译根本指不到任何东西。提示词
整体是中文也照样保留英文原词。

## 修复

- `set_spec` 引用了 `cardInputSchema.shape.mode` 这个不存在的字段，取到
  `undefined` 后注册时抛 `Cannot read properties of undefined (reading
  '_zod')`，导致 **catimation 全部 MCP 工具一起起不来**。TypeScript 早就
  报了 TS2551，被当成预存基线放过 —— Zod schema 上的属性不存在不是类型
  洁癖，是只在服务器启动时才炸的运行时炸弹。
- `duration` 的 `z.union([z.literal(-1), ...])` 会生成 `anyOf`，客户端侧
  校验器对它支持参差不齐，合法的 `-1` 在到达我们之前就被拦下。三处全换成
  朴素整数区间；按模型分档的校验交给 `validateSeedanceRequest`。
- 两条守护测试:任何工具 schema 出现 `undefined` 字段或顶层 union 就失败。
  这类问题的特征是本地全绿、线上全红。
