# v4.4.1 发布说明

> 发布渠道：腾讯云 COS 热更新（`releases/latest.yml`）+ GitHub Release 兜底
> 基线版本：v4.4.0

## 概览

本版把 Seedance 提示词工程从“每次强制加载完整结构叶子”调整为轻重分流：
仅简单单镜连续任务走路径 A，可跳过 `seedance-cinematic-format`；复杂、多镜、
混合媒介或需展开导演/作品参考任一命中即走路径 B，再加载完整媒介 profile。
路径 B 条件优先于生成、编辑、延长、组合等任务类型。两条路径只在内容展开程度
和加载成本上不同，八大要素、12 项内容与五大必备块均不能缺失。

## 提示词结构

- 12 项从固定方括号字段改为内容覆盖清单；标题、顺序、空行和散文形式自由。
- 路径 B 覆盖总体设定、镜头流程、风格与约束三组语义，但不强制三段或固定标题。
- 八大核心要素全部必填；路径 A 可把场景、光影、运镜、风格、画质和约束压缩
  为短语或自动补全，但不能省略。
- 五大内容块保持必备：演出核心与递进、收束方向、品质绝对基准、详细高品质参考、
  监督演出思考。
- 百分比只表达语义收束方向，不作为 Seedance API 参数或可保证结果的模型权重。

## 素材引用与故事板

- Skill 写作使用 `@图片N / @视频N / @音频N`，应用在工具边界归一为
  `图片N / 视频N / 音频N`；两层语义不再混称。
- 长图、九宫格、故事板和电影美术设定板由用户在“拆格精确执行”与“整板低约束
  氛围参考”之间选择；用户要求直出时采用推荐默认，不阻塞流程。
- 整板参考继续强制“提示词主导 / 氛围板低约束”前缀，不冒充身份锚点或首帧。

## Grok 4.5 Providers

- 新增独立 `Right.Codes Grok` Provider，使用
  `https://right.codes/grok/v1` 的 Responses API，默认模型为 `grok-4.5`。
- 新增独立 `API Yi Grok` Provider，复用 `https://api.apiyi.com/v1`；
  仅已开通 Grok 渠道的 API易 Key 可用。
- 两条 Grok 通道固定只展示 `grok-4.5`：Right.Codes 按其官方配置显示 1M，
  API易按模型能力页显示 500K；切换 Provider 时同步切换模型和上下文。
- Grok Reasoning 提供 Auto、Low、Medium、High；API易明确不支持 Priority
  Processing，因此不展示无法兑现的 Fast 开关。
- Grok 与原 Right.Codes Codex 通道复用同一网关密钥，无需重复录入。
- API Yi Grok 同样复用已有 API易密钥，无需重复录入。
- 自定义 Provider 的 Codex namespace 工具会在本地兼容层转换为标准 Responses
  function，并保留 `web_search` 等官方工具；流式函数调用返回后再恢复 Codex 命名空间。
- 已用内置 Codex CLI 0.144.5 分别完成 Right.Codes 与 API易真实 Responses 回合，
  收到 `GROK_OK` / `APIYI_GROK_OK` 并正常结束 turn。
