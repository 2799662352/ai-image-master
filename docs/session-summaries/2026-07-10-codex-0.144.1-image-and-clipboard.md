# Codex 0.144.1、批量生图与剪贴板图片对齐

日期：2026-07-10
状态：已实现并通过定向回归、离线 Codex 冒烟与生产构建

## 目标

本批次解决三类问题：

1. `generate_images` 无法一次处理 9 张及以上图片，以及共享参考图在批量任务中被重复读取、重复编码造成的内存和请求压力。
2. bundled Codex 从 0.143.0 对齐到 0.144.1，包括模型目录、推理力度、上下文窗口和 MCP 鉴权交互。
3. Windows 用户无法把其他软件的截图直接粘贴到 Agent 对话框，以及多张截图都叫 `image.png` 时 React key 冲突和误删。

## 批量生图与 HTTP 413

- `generate_images.prompts` 上限由 8 提升到 20。
- 渲染层使用 3-worker 有界并发池；结果保持 prompt 原顺序，单张失败不会让整个批次丢失。
- 共享参考图只解析一次，再复用到每个子任务，避免同一原图被读取和 base64 编码 N 次。
- Windows 本地路径按大小写不敏感和统一斜杠去重；data URL 与 HTTP URL 保持字节级大小写。
- 参考图继续保留原始字节，不做隐式 1024px/JPEG 压缩。若上游返回 413，由 Agent 使用 `ffmpeg-win` 生成压缩副本后重试，不覆盖原图。
- `catimation-image` 的首方内置版和插件版已同步该约定。

## Codex 0.144.1 对齐

- `package.json.codexCliVersion` 更新为 `0.144.1`。
- 协议层新增 `model/list`，离线冒烟会实际读取 bundled binary 的模型目录。
- 聊天模型选择器新增 GPT-5.6 Luna、Terra、Sol，并隐藏 GPT-5.4 以下的旧模型。
- 带推理力度的 UI 选项拆成原生 `turn/start.model` + `turn/start.effort`，不再把 `-low/-high/-xhigh` 当作模型 slug 发送。
- 移除全局 `model_context_window=272000`：0.144.1 的 GPT-5.6 目录可声明 372K，继续硬编码会静默损失上下文；仍保留 220K 自动压缩阈值用于防范 relay 请求体过大。
- 支持 `mcpServer/elicitation/request` 的 0.144 响应信封和专用 UI，可显示外部服务登录 URL。
- 冒烟测试使用隔离的临时 `CODEX_HOME`，避免用户配置污染，并对 Windows 临时目录锁做容错清理。

## 截图直接粘贴

- `MentionInput` 监听标准 `ClipboardEvent`，从 `clipboardData.items` 读取 `image/*`，并兼容只提供 `clipboardData.files` 的剪贴板实现。
- 图片以原始 `ArrayBuffer` 进入附件链；发送时由 `AttachmentService` 内容寻址落盘，最终作为 Codex `localImage` 路径发送。
- 普通文本粘贴不调用 `preventDefault()`，原有 textarea 行为不变。
- 单个内存附件上限仍为 100MB；路径型附件仍走主进程流式读取，不跨 renderer IPC 搬运整文件。
- composer 提示加入 `Ctrl+V image`，让该能力可发现。

## 同名附件身份

剪贴板截图通常都叫 `image.png`，文件名不能作为 React key 或删除条件。

- 每个 composer 附件在进入 Zustand store 时获得稳定、唯一的 `composerId`。
- `AttachmentChips` 使用该 ID 作为 React key，并按附件身份删除，因此同名截图不会重复/消失，也不会一键删掉全部同名项。
- `composerId` 是不可枚举的 renderer-only 元数据，不进入 IPC、持久化 JSON 或历史消息契约。
- 对热更新前已存在、没有 `composerId` 的内存对象，使用 `WeakMap` 提供稳定兼容 key。
